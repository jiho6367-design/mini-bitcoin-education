# 블록체인 실습실과 실제 Bitcoin의 차이

2026-11-17 기준 `blockchain-practice` 팀 앱을 설명합니다 **기초 실습은 계정 잔액·거래 순번**, **공동 실습은 교육용 UTXO**, **넌스 찾기는 독립 해시 탐색**을 사용합니다 이 셋의 코인과 결과는 서로 합쳐지지 않습니다 이전 개인 React 앱의 비교표는 [보존한 원문](archive/personal-react/docs/bitcoin-differences.md)에 있습니다

## 공통으로 관찰하는 개념

개인키로 거래 내용을 승인하고 공개키로 서명을 검증합니다 거래 접수와 블록 확정은 다르며, Nonce를 바꿔 실제 해시를 계산해 PoW 조건을 찾습니다 수신 노드는 거래·블록을 자기 상태에 맞춰 다시 검증합니다 서명은 암호화가 아니며 해시는 복호화하는 데이터가 아닙니다

실제 Bitcoin의 일반 거래는 이전 출력에서 입력을 만들고 아직 소비하지 않은 출력인 UTXO를 소비합니다 이 개념은 공동 실습에 반영했고, 기초 실습은 입문 흐름을 위해 계정 모델을 사용합니다 [Bitcoin 거래 안내](https://developer.bitcoin.org/devguide/transactions.html)

## 장부와 거래

| 항목 | 실제 Bitcoin | 기초 실습 | 공동 실습·교육 엔진 |
| --- | --- | --- | --- |
| 잔액 모델 | UTXO와 지출 조건 | 주소별 정수 잔액과 송신자 거래 순번 | `txId:outputIndex` UTXO, 입력 선택·예약·소비 |
| 시작 코인 | 프로토콜의 발행 규칙 | 새 지갑당 한 번 50코인 faucet 거래, 채굴 후 확정 | Genesis에서 A/B/C에 각 100 기본 배정, 새 방은 각 1~10000 선택 |
| 추가 참가·재접속 | 지갑 접속 자체는 발행 원인이 아님 | 주소당 faucet 중복 거부 | 기존 배정·장부 유지, 참가자 추가로 재발행하지 않음 |
| 송금 | 입력·출력·수수료·스크립트 규칙 | 계정 잔액·순번 검사, UTXO와 거스름돈 없음 | 한 지갑의 확정 입력, 수신·거스름돈 출력, 정수 수수료 |
| 채굴 보상 | 블록 보조금·수수료·성숙 규칙 | 10코인, 별도 UTXO 성숙 모델 없음 | 별도 보상 지갑에 50+수수료, 100블록 성숙 |
| 주소 | 표준 주소와 스크립트 유형 | `SHA256(공개키 바이트)` 64자리 hex | `mini_` + `SHA256(압축 공개키 바이트)` |
| 서명 | 거래 유형에 따른 프로토콜 규칙 | secp256k1 ECDSA, 자체 거래 원문 | secp256k1 ECDSA, 고정 배열 JSON 원문과 64바이트 compact 서명 |
| 키 관리 | 지갑 구현에 따라 백업·키 보관 방식이 다름 | 교육용 키를 팀 서버 기록에 보관 | 교육용 키를 팀 서버 체크포인트에 보관, 브라우저 소유권·역할로 조회/서명 제한 |

Bitcoin의 블록 보상은 coinbase 거래에 기록되고 수수료도 포함할 수 있으며 coinbase 출력에는 100블록 성숙 규칙이 있습니다 공동 실습은 이 관계를 관찰하도록 구현했지만 보조금 반감기 등 전체 발행 정책을 구현하지 않았습니다 [Bitcoin 블록·발행 안내](https://developer.bitcoin.org/devguide/block_chain.html#transaction-data)

공동 실습에서 **잔액 100 / 사용 가능 0**은 코인이 사라진 뜻이 아닐 수 있습니다 초기 100 UTXO로 송금 10·수수료 1을 제출하면 입력 전체 100이 예약되고, 채굴·전파 후 수신 10·거스름돈 89·수수료 1로 반영됩니다 미성숙 채굴 보상은 별도로 구분합니다

## 해시·PoW·네트워크

| 항목 | 실제 Bitcoin | 팀 앱 |
| --- | --- | --- |
| 블록 헤더 | 80바이트 프로토콜 헤더, 이중 SHA-256 | 기초는 구분자로 연결한 텍스트, 교육 엔진은 JSON 배열, 각각 단일 SHA-256 |
| 거래 목록 | Bitcoin 해시·바이트 순서 규칙의 Merkle tree | 기초는 교육용 Merkle tree, 교육 엔진은 실제 거래 필드 전체를 정규화한 목록 해시 |
| 목표값 | `nBits`로 표현한 수치 target | 앞의 16진수 0 개수로 목표를 쉽게 표현 |
| 난이도 | 네트워크 규칙에 따른 조정 | 기초 1~5·높이별 변경 기록, 교육 엔진 1~4·실습별 고정 |
| 노드 | 별도 실행 주체들이 블록·거래를 P2P로 교환 | Flask 프로세스 한 개 안의 A/B/C 독립 상태 |
| 전파 | 실제 네트워크 프로토콜 | 기초의 모의 전달, 교육 엔진의 수동·자동 FIFO 메시지 큐 |
| 체인 선택 | 유효성·누적 작업량에 따른 선택 | 기초의 유효한 동료 체인 복구, 교육 엔진의 분기·누적 작업량·재구성 학습 모델 |
| 채굴 비교 | 실제 채굴기의 독립 작업과 네트워크 경쟁 | 기초는 같은 서버의 순환 계산, 공동 경쟁도 한 서버의 스케줄러로 진행 |
| 저장 | 노드 구현이 장부를 보관 | 로컬 별도 SQLite, 운영 Neon PostgreSQL, 서버 재시작 후 저장 장부 복원 |

Bitcoin의 헤더·Merkle root·target 형식은 공식 참조의 바이트 규칙을 따릅니다 팀 앱의 단일 SHA-256과 교육용 직렬화는 그 형식과 호환되지 않습니다 [Bitcoin 헤더·Merkle tree 참조](https://developer.bitcoin.org/reference/block_chain.html)

Bitcoin의 피어는 데이터를 검증한 뒤 다른 피어에 전달합니다 팀원의 브라우저가 HTTP·WebSocket으로 같은 Flask 서버에 접속하는 구조와는 다릅니다 여러 팀원이 접속해도 A/B/C가 서로 다른 PC의 P2P 노드가 되지는 않습니다 [Bitcoin P2P 안내](https://developer.bitcoin.org/devguide/p2p_network.html)

교육 엔진의 난이도 `d`는 `target = 2^(256−4d)−1`, 성공 확률 `16^-d`로 표현합니다 따라서 난이도 1 증가 시 평균 계산량은 16배지만 한 번의 실제 발견 시간은 달라질 수 있습니다 이 숫자는 Bitcoin 네트워크의 difficulty 값과 같은 척도가 아닙니다

## 넌스 찾기 화면의 의미

넌스 찾기는 `SHA256(UTF8(메시지 + 10진수 넌스))`가 목표를 만족하는 값을 찾습니다 uint64 넌스를 사용하고 결과를 독립 재검증합니다 Bitcoin의 80바이트 헤더 채굴·거래 확정·코인 발행과 연결하지 않습니다

브라우저 CPU·WebGPU·CPU+GPU는 접속 기기에서 실행합니다 GPU 미지원·검증/계산 실패·UTF-8 메시지 35바이트 초과 시 CPU로 전환하며 실제 연산 방식·전환 이유·완료 수를 표시합니다 Python/C 고급 모드는 명시적으로 켠 로컬 PC 서버에서만 사용할 수 있고 공개 Render에서는 꺼집니다 실제 장치 조건은 [설계](architecture.md)와 [PC 엔진 안내](../experiments/blockchain-practice/native_hashcash/README.md)를 따릅니다

넌스 기록은 그 브라우저에 최근 50개를 저장하므로 다른 기기에 자동 공유되지 않습니다 반면 기초·공동 장부는 서버 DB에 저장합니다 서버 재시작으로 저장 기록이 없어지지 않는 것과 무료 서비스가 항상 즉시 응답하는 것은 별개입니다

## 발표·보고서에서 사용할 표현

- **실제로 수행**: secp256k1 서명 검증, SHA-256, Nonce 반복 계산, 규칙 검증, DB 저장·복원
- **교육용 모델**: 계정/UTXO 장부, A/B/C 노드와 전파, 채굴 경쟁·분기·재구성, 코인 발행
- **구현 범위 밖**: Bitcoin 네트워크 접속, Bitcoin 주소·거래·블록 호환, 실제 자산 지갑, 탈중앙 운영, 다중 서버 합의

변조 실험에서 검증 실패나 재채굴 비용을 관찰할 수 있어도 실제 Bitcoin의 공격 비용·확률적 확정·경제적 보안을 검증한 결과로 해석하지 않습니다 코드 근거와 현재 검증 범위는 [설계](architecture.md), [검토 반영 기록](review-resolution.md), [팀 검증 기록](../experiments/blockchain-practice/VERIFICATION.md)에 있습니다
