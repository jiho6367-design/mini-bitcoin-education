# 실제 Bitcoin 대비 단순화와 용어

## 유지하는 개념

- 개인키로 거래 내용에 서명하고 공개키로 서명을 검증한다. 서명은 암호화가 아니다.
- 코인은 지갑 객체의 숫자가 아닌 UTXO로 표현한다. 입력을 한 번 소비하고 수신·거스름돈 출력을 만든다.
- Mempool은 노드별 미확정 거래 목록이다. 등록은 블록 포함과 다르다.
- PoW는 후보 헤더의 Nonce를 바꾸며 목표값 이하의 해시를 탐색한다. 찾기는 반복 계산이 필요하고 검증은 빠르다.
- Previous Hash는 블록을 연결한다. 각 노드는 서명·거래·블록을 자기 상태로 검증한다.
- 변경은 가능하지만 서명·해시·연결·PoW 검사에서 드러난다. 실제 Bitcoin의 공격 비용과 확률적 확정은 이 작은 모델의 보안 수준과 다르다.

## 비교표

| 항목 | 실제 Bitcoin | Mini Bitcoin |
|---|---|---|
| 초기 코인·발행 | coinbase 거래와 블록 보조금, 수수료, 성숙 규칙 | Genesis가 첫 지갑에 100 배정. 채굴 보상 없음 |
| UTXO | 다양한 잠금·해제 조건, 스크립트 | 공개키에 대응하는 교육용 주소 소유권만 검사 |
| 거래 기능 | 복수 서명자, 수수료, 잠금 시간, 미확정 거래 연결 등 | 한 송신 지갑, 정수 금액, 수수료 0, 확정 출력만 사용 |
| 서명 | 거래 유형에 따라 ECDSA 또는 Schnorr 등 | secp256k1 ECDSA와 고유한 교육용 서명 원문 |
| 주소·지갑 | 여러 표준 주소·HD 키·복구 기능 등 | mini_ + SHA-256(공개키 바이트), 지갑마다 단일 키 쌍 |
| 직렬화·해시 | 프로토콜 바이너리 형식과 용도별 해시 규칙 | 고정 배열 JSON, 단일 SHA-256 |
| 거래 목록 | Merkle root와 Merkle proof | 전체 실제 거래 목록의 단일 해시 |
| PoW | 80바이트 헤더, 이중 SHA-256, 수치 target | 교육용 JSON 헤더, 단일 SHA-256, 16진수 선행 0 |
| 난이도 | 네트워크 규칙에 따른 주기적 자동 조정 | 실습별 1~4로 고정, 변경하려면 새 실습 |
| 노드 | 서로 다른 장치·프로세스의 P2P 통신 | 백엔드 프로세스 하나 안의 독립 상태 3개와 메시지 대기열 |
| 체인 선택 | 유효한 체인들의 누적 작업량을 비교, 필요 시 재구성 | 한 번에 한 채굴 작업. 분기 경쟁·복구 제외 |
| 키 보관·서명 | 지갑이 사용자의 기기에서 개인키를 보관하고 서명. 노드는 서명된 거래만 받음 | 백엔드가 교육용 개인키를 보관하고 서명. 화면은 펼쳐 볼 때만 개인키를 받음 |
| 채굴 실행 | 채굴자가 스스로 계속 계산 | 화면이 요청할 때마다 백엔드가 다음 Nonce들을 계산. 화면이 없으면 진행하지 않음 |
| 데이터 | 영속 저장, 동기화, 실제 키 관리 | 실습 상태는 백엔드 메모리에만 보관하고 새로고침·백엔드 재시작 시 초기화. 화면 테마 선택값만 브라우저에 저장 |

교육용 난이도 2는 Bitcoin 네트워크의 숫자 difficulty=2와 같은 의미가 아니다. 여기서는 16진수 앞 두 자리가 0인 해시를 뜻한다. 목표값을 함께 표시하여 선행 0이 수치 비교의 쉬운 표현임을 설명한다.

## 용어 카드

| 용어 | 입문자 설명 |
|---|---|
| Wallet | 키를 관리하고 사용할 수 있는 출력을 찾아 거래를 만드는 도구 |
| 개인키 / 공개키 | 작성 권한을 증명하는 비밀 정보 / 서명을 검증하는 공개 정보 |
| 주소 | 수신 대상을 표현하는 식별자. 공개키 자체와 동일하지 않음 |
| Hash | 데이터에서 계산한 고정 길이 값. 암호화와 달리 복호화하지 않음 |
| 전자서명 | 개인키 소유자가 특정 내용을 승인했음을 공개키로 검증하는 값 |
| UTXO | 아직 소비하지 않은 거래 출력. 지갑 잔액은 관련 UTXO의 합 |
| 거스름돈 | 사용한 입력 총액에서 송금액을 뺀 값을 자기 주소로 돌려주는 출력 |
| Mempool | 한 노드가 받아 두었지만 아직 체인에 반영하지 않은 거래 |
| Nonce | 새로운 해시를 시도하기 위해 바꾸는 후보 헤더의 값 |
| PoW | 조건에 맞는 해시를 찾았다는 검증 가능한 계산 결과 |
| Previous Hash | 바로 이전 블록을 가리키는 해시 |
| Genesis | 체인의 시작점. 이 실습은 초기 코인 배정도 여기서 수행 |
| Node | 메시지를 받고 자기 규칙·상태로 검증하여 체인을 유지하는 참여자 |
| 확인 수 | 거래가 포함된 블록과 그 이후 블록을 통해 누적되는 확인. 앱은 후속 블록 수를 따로 표시 |
