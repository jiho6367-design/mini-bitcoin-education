## 접속과 화면 선택

PC와 휴대폰에서 링크를 열면 바로 사용할 수 있습니다 온라인 실습에는 Python·Node.js 설치나 사용자 PC의 서버 실행이 필요하지 않습니다 무료 서버가 쉬고 있었다면 준비 안내를 보면서 기다리세요 준비가 끝나면 자동으로 연결됩니다

상단에서 필요한 화면을 고릅니다

| 화면 | 쓰임 | 기록 위치 |
| --- | --- | --- |
| 기초 실습 | 지갑·서명·채굴·변조·복구를 혼자 순서대로 배우기 | 서버의 브라우저별 실습 공간 |
| 공동 실습 | 같은 링크에서 팀원과 하나의 장부 조작하기 | 서버의 방 코드별 공동 장부 |
| 넌스 찾기 | 메시지 뒤 숫자를 바꿔 실제 SHA-256 조건 찾기 | 찾은 결과 최근 50개를 현재 브라우저에 저장 |

기초와 공동 실습은 규칙과 장부가 다릅니다 화면을 옮겨도 두 장부가 합쳐지지 않습니다 `/advanced`는 이전 통합 실습과 보관함을 위한 호환 경로이며 공개 메뉴에서는 제외합니다

## 기초 실습을 혼자 따라 하기

처음에는 **시작하기 → 전체 실습 안내**의 6단계와 각 화면 위의 **실행·확인** 안내를 따라갑니다 **시연 영상 보기**를 펼치면 한국어 설명 음성과 클릭 안내 자막이 있는 4분 33초 영상을 볼 수 있습니다

1. **지갑 → 지갑 이름**에 Alice를 적고 **지갑 생성**을 누릅니다 Bob도 같은 방식으로 만듭니다 새 지갑마다 50코인 지급 거래가 대기열에 생기며 아직 확정 잔액은 아닙니다
2. **채굴 → 한 노드 채굴**을 엽니다 **관찰 노드**를 Node A로 두고, **보상을 받을 지갑**은 Node A 채굴자 지갑으로 고릅니다 처음에는 **목표 난이도**를 2로 정한 뒤 **적용**을 누릅니다
3. **연속 실행**을 누르고 블록 발견을 기다립니다 지급 거래가 포함되면 Alice와 Bob의 확정 잔액이 각각 50이 됩니다 Node A 채굴자 지갑에는 별도로 보상 10이 생깁니다
4. **거래·서명**에서 Alice → Bob, 송금액 20을 고르고 **거래 작성 → 개인키로 서명 → 검증·제출** 순서로 누릅니다 작성·서명만으로 송금이 확정되지는 않습니다 지갑·금액·관찰 노드를 바꾸면 초안과 서명이 초기화됩니다
5. **거래 대기열**에서 제출한 송금을 확인한 뒤 **채굴**로 이동합니다 한 노드로 계속 채굴하거나 아래의 **세 노드 비교**를 사용합니다
6. 송금을 포함한 블록이 반영되면 **지갑**에서 Alice 30, Bob 70을 확인합니다 이 값은 채굴 보상을 노드 지갑으로 받은 예시입니다 Alice나 Bob을 보상 지갑으로 골랐다면 보상만큼 잔액이 더해집니다

**새 실습**은 별도 실습 공간을 만들고, **초기화**는 현재 실습을 다시 시작하는 조작입니다 확인창의 대상을 읽고 사용하세요 진행 기록을 확인하려면 **활동 기록 → JSON 내보내기**를 사용할 수 있습니다 JSON은 관찰·제출용 기록이며 DB 복원 파일이 아닙니다

### 세 노드 채굴 비교

**채굴 → 세 노드 비교**에서 계산 속도를 고른 뒤 **한 번씩 계산**으로 A·B·C의 실제 해시 표본을 확인할 수 있습니다 **세 노드 비교 시작** 또는 **계속 비교**로 첫 블록을 찾을 때까지 진행합니다

결과에서 발견 노드, 노드별 시도 횟수·Nonce·실제 해시, 블록 전달·검증 결과를 비교합니다 먼저 찾은 블록을 연결된 다른 노드가 검증합니다 발견 노드와 시도 횟수는 실행마다 달라질 수 있습니다

세 노드 비교는 한 서버에서 A·B·C가 번갈아 계산하는 교육 모델입니다 실제 컴퓨터 세 대의 병렬 성능을 측정하는 기능은 아닙니다 **일시정지·계속 비교·비교 중지**로 작업을 제어할 수 있습니다

### 변조를 관찰하고 복구하기

기초 **블록·변조**는 선택한 노드의 체인을 실제로 변경하므로 먼저 정상 노드 A를 남겨 두고 **관찰 노드**를 B로 바꿉니다

1. 송금이 들어 있는 블록과 **서명된 송금 거래**를 고릅니다 거래 #0의 채굴 보상과 구분하세요
2. 변경할 금액이나 수신 주소를 정하고 **검증 실험 방식**을 고릅니다
3. **대상 확인 후 변조**를 누른 뒤 블록 해시·Merkle Root·PoW·서명 등의 실패 이유를 읽습니다
4. **다른 노드와 동기화**를 눌러 정상인 온라인 노드의 유효 체인으로 복구합니다 **노드·동기화**에서 세 노드의 검증 결과와 끝 해시를 비교합니다

내용 변경, Merkle·해시 재계산, 이후 블록 재채굴은 서로 다른 실험입니다 해시와 PoW를 다시 맞춰도 수정한 송금의 원래 서명이 유효해지는 것은 아닙니다 재채굴은 복사본에서 진행되며 완료 전에 취소하면 원래 체인이 유지됩니다

## 공동 실습 시작하기

팀원이 준 참여 링크가 있다면 **공동 실습**에서 별명을 적고 **기존 실습에 입장**을 누릅니다 공유 링크의 방 코드는 자동으로 채워집니다 기록을 이어갈 때는 **새 실습 만들기**를 누르지 않습니다

혼자 시험하거나 다른 팀과 새로 시작하려면 **새 실습 만들기 → 별명·팀별 초기 코인 입력 → 새 실습 시작**을 누릅니다 초기 코인은 1~10000 사이 정수이며 A·B·C에 같은 금액을 한 번 배정합니다 새 방에는 별도 링크가 생기고 기존 링크와 장부는 유지됩니다

처음에는 100으로 시작하면 아래 예시를 그대로 따라갈 수 있습니다 입장 후 표시되는 방 링크를 팀원에게 공유하세요 교사 접속이나 교사용 비밀코드는 일반 팀 실습에 필요하지 않습니다

### 혼자 끝까지 진행하기

**쉬운 실습**에서 현재 켜진 버튼 하나씩 누릅니다

1. **팀 A로 시작**으로 A 역할을 맡습니다 B·C 담당자가 없어도 서버의 B·C 노드는 거래와 블록을 검증합니다
2. **자동 전달 켜기**를 누릅니다
3. 받는 팀 B, 송금액 10, 수수료 1을 확인합니다 **송금 내용 확인 → 전자서명하기 → 거래 보내기**를 차례로 누릅니다
4. 거래 전파가 끝나면 **채굴 준비 → 채굴 시작**을 누릅니다 선택한 A 노드 하나가 실제 해시를 계산합니다
5. **결과 보기**에서 같은 거래가 A·B·C 모두의 블록에 포함됐는지 확인합니다 초기 100의 예시는 A 89, B 110, C 100이며 채굴 보상은 별도 보상 지갑에 쌓입니다
6. **지금 저장**과 저장 상태를 확인하고 같은 링크를 보관합니다 새로고침 후 같은 장부를 이어갈 수 있습니다 서버 재시작 후에는 역할을 다시 선택하고 멈춘 계산을 직접 재개합니다

이미 대기 거래가 있으면 **대기 거래 이어서 보기**로 그 거래를 마무리하세요 사용 가능액이 부족하다고 새 거래를 계속 만들 필요는 없습니다

### 팀원과 함께 진행하기

각자 별명으로 같은 링크에 입장하고 비어 있는 A·B·C 중 하나를 맡습니다 다른 팀원이 맡은 역할에는 그 별명이 표시됩니다 역할을 맡지 않은 참가자는 관찰할 수 있습니다 한 명이 자동 전달·공통 채굴 버튼을 진행하고, 각 팀의 송금은 해당 역할을 맡은 사람이 서명합니다

**직접 조작 · 팀 선택과 거래·채굴 상세**를 펼치면 거래·채굴·노드 화면을 직접 조작할 수 있습니다 **한 노드 채굴**은 선택 노드 하나만 계산하며, **채굴 경쟁**은 세 후보 준비 후 담당자들이 참여해 진행하는 별도 방식입니다

**공통 실습 가이드**를 펼치면 역할 선택 → 자동 전달 → 거래 만들기 → 거래 전달 확인 → 채굴 → 결과 확인이 나옵니다 완료 체크와 다음 할 일은 선택한 거래와 현재 노드 상태로 갱신됩니다 설명 화면만 넘겨서는 거래·채굴이 실행되지 않습니다 분기나 재구성으로 현재 결과가 달라지면 완료 표시도 달라질 수 있습니다

### 잔액은 있는데 사용 가능이 0인 경우

공동 실습은 UTXO 모델입니다 초기 100짜리 입력으로 송금 10·수수료 1을 제출하면 입력 100 전체가 예약됩니다 이때 확정 잔액 100, 사용 가능 0, 대기 거래 예약 100으로 보일 수 있습니다 블록 반영 후 거스름돈 89를 사용할 수 있습니다

추가 참가나 재접속은 초기 코인을 더 주지 않습니다 현재 잔액은 송금·수수료에 따라 달라지며, 보상 지갑의 새 채굴 보상에는 100블록 성숙 규칙이 적용됩니다 기초 실습의 50코인 지급·10코인 보상 규칙과 구분하세요

## 넌스 찾기

**넌스 찾기**에서는 장부 송금과 별도로 접속한 기기가 실제 해시를 계산합니다

1. 메시지를 적고 목표 난이도를 2~3으로 정합니다
2. **연산 방식**을 CPU로 두면 GPU 준비 없이 바로 시작할 수 있습니다 자동·GPU·CPU+GPU도 지원하며 실제 사용 장치와 전환 이유가 결과에 표시됩니다
3. **탐색 시작**을 누르고 발견한 넌스·SHA-256 해시·계산 횟수를 확인합니다 오래 걸리면 **중지**할 수 있습니다
4. **해시 다시 검증**을 눌러 같은 메시지·넌스의 해시와 목표 조건이 일치하는지 확인합니다
5. **찾은 기록**에서 결과를 확인하고 새로고침해 보세요 최근 50개는 같은 브라우저에 남습니다 다른 기기나 공동 장부에는 저장되지 않습니다

규칙은 `SHA256(UTF8(메시지 + 10진수 넌스))`입니다 공백·줄바꿈도 그대로 계산합니다 난이도는 선행 16진수 0 개수이며 1 증가할 때 평균 계산량은 16배지만 개별 발견 시간은 다릅니다

Python·C 고급 모드는 선택 사항으로 로컬 PC에서 실습실과 필요한 엔진을 실행한 경우에만 사용합니다 무료 온라인 서버에서 고급 PC 모드를 고르면 안내 후 브라우저 CPU로 전환합니다 설치와 조건은 [앱 실행 안내](../experiments/blockchain-practice/README.md)를 참고하세요

## 저장·연결·화면 설정

온라인의 기초·공동 기록은 Neon PostgreSQL에 저장하므로 사용자 PC를 꺼도 공개 링크는 운영 서버에서 제공됩니다 무료 서비스 제한·준비 시간·연결 중단은 있을 수 있습니다 기초 실습의 소유 연결과 공동 참여 정보는 같은 브라우저에서 이어 사용하므로 브라우저 데이터를 지우거나 다른 기기를 쓰면 같은 개인 실습에 자동 접근하지 못할 수 있습니다 공동 장부는 기존 방 링크에서 이름으로 다시 참여할 수 있습니다

연결 복구는 읽기 요청을 재시도합니다 거래·서명·채굴 같은 변경 요청은 자동으로 다시 보내지 않습니다 처리 여부가 불확실하다는 안내가 나오면 연결 후 현재 장부를 먼저 확인하고 필요한 조작만 다시 하세요

상단 **화면 테마**의 시스템·라이트·다크 선택은 기초·공동·넌스 화면에서 유지됩니다 테마를 바꿔도 장부나 거래를 초기화하지 않습니다 점선 밑줄 용어를 터치하거나 마우스를 올려 뜻을 보고 **용어 사전**과 **구성도**에서 자세한 설명을 확인할 수 있습니다

## 문제 해결

| 증상 | 확인·조치 |
| --- | --- |
| 첫 접속에서 버튼이 준비 중 | 준비 안내가 끝날 때까지 기다립니다 정상 응답 뒤 자동으로 연결됩니다 |
| 연결이 계속 끊김 | 인터넷 연결을 확인하고 같은 링크를 다시 엽니다 처리 여부가 불확실한 거래는 장부부터 확인합니다 |
| 지갑에 50이 바로 안 보임 | 기초 지급 거래를 먼저 채굴해 확정했는지 확인합니다 |
| 공동 사용 가능액이 0 | 예약된 대기 거래 또는 보상 성숙 대기를 카드에서 확인하고 기존 거래를 이어갑니다 |
| 서명·제출 버튼 비활성 | 거래 작성 → 서명 → 제출 순서와 현재 팀 역할을 확인합니다 |
| 공동 채굴 시작 버튼 비활성 | 후보 준비를 먼저 하고, 연결·저장 상태가 정상인지 확인합니다 |
| 세 노드 결과가 다름 | 전달 대기열·자동 전달·오프라인·검증 결과를 확인합니다 기초의 무효 노드는 정상 노드와 동기화합니다 |
| 새로고침 뒤 역할이 없음 | 같은 공동 링크에서 역할을 다시 선택합니다 기록을 새로 만들 필요는 없습니다 |
