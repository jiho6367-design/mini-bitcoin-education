# 사용 안내

## 실행과 초기화

Node.js 24.x와 Python 프로젝트 도구 uv가 필요합니다. 실행 중에는 Python 백엔드 하나만 있으면 됩니다.

1. **화면 빌드(처음 한 번):** `frontend` 폴더에서 `npm.cmd ci` → `npm.cmd run build`. 빌드 결과는 `frontend/dist`에 생깁니다.
2. **실행:** `backend` 폴더에서 `uv sync` → `uv run mini-bitcoin-backend` 후 `http://127.0.0.1:8000`을 엽니다.

백엔드가 빌드된 화면과 API를 같은 주소에서 함께 제공합니다. 시작할 때 터미널에 **화면과 API를 함께 제공합니다**가 표시되는지 확인하세요. **빌드된 화면이 없어 API만 제공합니다**가 표시되면 1번을 실행한 뒤 백엔드를 다시 시작합니다. 화면 소스를 바꾼 뒤에도 1번의 빌드를 다시 해야 바뀐 화면이 보입니다.

화면을 수정하면서 바로 확인하려면 서버 두 개를 사용합니다. `backend`에서 `uv run mini-bitcoin-backend --api-only`, `frontend`에서 `npm.cmd run dev`를 실행하고 표시된 주소(`http://127.0.0.1:5173`)를 엽니다. 이때는 화면 개발 서버가 `/api` 요청을 백엔드로 전달합니다.

화면은 실습의 모든 계산을 백엔드에 요청합니다. 지갑·개인키·거래·블록체인 등 실습 상태는 백엔드의 메모리에만 있으므로 새로고침·브라우저 닫기·백엔드 재시작으로 초기화됩니다. 실습 저장·복원 기능은 없습니다. 화면 테마 설정만 브라우저에 보관합니다.

시작 화면에서 난이도를 고르고 **예제 실습 시작** 또는 **직접 시작: Alice 지갑 생성 → Bob 지갑 생성 → 생성한 지갑으로 시작**을 사용합니다. 최초 두 지갑 이름은 설명을 위해 Alice와 Bob으로 고정합니다. 추가 지갑에는 코인을 배정하지 않습니다.

실습 중 난이도를 바꾸려면 시작 화면의 **난이도를 바꿔 새 실습**을 누르고 초기화를 확인합니다. 이전 실습을 보존하면서 난이도만 바꾸지는 않습니다.

## 화면 테마와 버전

상단 **화면 테마**에서 **라이트·다크·시스템**을 선택합니다. 처음 방문한 브라우저의 기본값은 시스템이며, 운영체제의 밝은/어두운 화면 설정을 따릅니다. 사용자가 고른 설정은 새로고침 후에도 유지됩니다. 시스템을 선택해 두면 운영체제 설정 변화에 맞춰 테마가 바뀝니다.

테마 전환은 글자·카드·입력창·버튼·검증 상태와 UTXO·노드 도식의 색을 바꾸는 화면 설정입니다. 실습을 초기화하거나 작성·서명한 거래, 검증 결과, Mempool·체인을 지우지 않습니다. 진행 중이거나 일시정지한 채굴 작업도 유지됩니다. 성공·실패·선택·비활성 상태는 색상뿐 아니라 문구·기호·형태로 구분합니다.

브라우저 `localStorage`에는 `mini-bitcoin-theme` 키로 테마 선택값만 저장합니다. 이 설정은 같은 브라우저의 같은 로컬 주소에서 유지됩니다. 백엔드(8000)·개발(5173)·미리보기(4173) 주소는 포트가 달라 저장 설정도 별개입니다. 지갑·개인키·블록체인·채굴 진행은 브라우저에 저장하지 않으며, 새로고침하면 새 실습이 됩니다. 시스템 설정과 저장된 테마 선택값은 별개입니다. 예를 들어 다크를 직접 선택하면 시스템이 라이트여도 다크를 유지합니다.

앱 화면의 버전은 `frontend/package.json`의 `version`에서 자동으로 표시하며 백엔드도 같은 버전을 사용합니다. 완료된 업데이트의 주요 내용은 저장소 루트의 [CHANGELOG](../CHANGELOG.md)에서 확인합니다.

## 지갑·거래

상단 관찰 노드를 선택하면 해당 노드가 알고 있는 잔액과 UTXO를 보여줍니다. 공개키·개인키는 펼쳐 보기에서 확인합니다. 개인키는 백엔드가 보관하며 **교육용 개인키 펼쳐 보기**를 열 때에만 화면으로 가져옵니다. 거래 작성과 서명도 백엔드가 수행합니다. 사용자의 기기에서 서명하는 실제 지갑과 다른 점입니다. 실제 개인키를 입력하거나 복구하는 기능은 없습니다.

보내는 지갑·받는 지갑·정수 송금액을 고르고 **1. 거래 작성 → 2. 전자서명 → 3. 검증·전파**를 누릅니다. 작성은 코인을 옮기지 않고, 서명도 블록 기록을 의미하지 않습니다. 검증 후 Mempool에 들어가며 채굴·블록 검증 후 확정 UTXO가 바뀝니다.

Alice의 단일 100 UTXO로 30을 송금하면 Mempool 대기 중에는 확정 잔액 100, 송금 가능 0입니다. 100 전체가 입력으로 예약되기 때문입니다. 블록 포함 후 거스름돈 70을 사용할 수 있습니다. 이는 30만 숫자로 차감하는 계좌 방식과 다릅니다.

화면·관찰 노드를 바꿔도 작성 폼·서명·현재 거래의 검증 결과는 유지됩니다. 검증 결과에는 실제 제출 노드를 표시하고, 잔액·UTXO 도식은 상단 관찰 노드의 상태를 표시합니다. 송신자·수신자·금액을 바꾸면 새로운 거래 추적을 시작합니다. 서명 원문·해시·서명·거래 ID는 상세 보기에서 비교합니다.

상단에서 작성 후에는 서명, 서명 후에는 검증을 현재 단계로 표시합니다. 검증 성공 직후에는 결과 관찰 단계이며 **검증 결과 확인 · Mempool로 이동** 또는 왼쪽 Mempool 화면을 선택하면 대기 상태로 이동합니다. 이 표시는 화면 관찰 순서입니다. 실제 검증과 Mempool 등록을 인위적으로 늦추지 않습니다. 검증 실패는 실패 기호로 표시하고 완료 체크를 붙이지 않습니다. 세 노드가 현재 거래를 블록에 수락해야 Blockchain 단계에 도달합니다. 기존 체인이 있어도 새 거래의 단계는 다시 시작합니다.

입력·출력 도식은 현재 거래의 입력 원본과 관찰 노드의 실제 UTXO·Mempool을 연결합니다. 같은 거래라도 블록을 아직 받지 않은 노드는 대기 상태, 받은 노드는 소비된 입력과 사용 가능한 새 출력을 표시할 수 있습니다. 실패 실험에서는 별도 사본의 검증 결과를 추적하며 이미 승인된 원본 거래는 유지합니다.

## 실패 실험

- **잔액 부족:** 101을 입력하고 거래 작성을 누릅니다. 만들 수 없는 이유를 표시합니다.
- **잘못된 서명:** 거래를 작성·서명한 후 전용 실험 버튼을 누릅니다. 서명만 잘못된 사본을 제출합니다.
- **이중 지출:** 유효 거래가 해당 노드 Mempool에 있을 때 전용 실험 버튼을 누릅니다. 같은 입력을 사용하는 별도 유효 서명 거래가 거부됩니다.
- **잘못된 PoW 블록:** 대기 거래가 있을 때 노드·블록체인의 전용 수신 실험 버튼을 누릅니다. 헤더 해시는 일치하지만 목표값을 만족하지 않는 블록을 수신 노드가 거부합니다.
- **변조:** 거래가 담긴 블록을 채굴한 뒤 변조 실험에서 금액 또는 헤더 시각을 바꿉니다. 첫 실패 위치와 각 관계의 상태를 확인합니다.

실패 실험은 실제 데이터 검증을 수행하며 미리 정한 성공·실패 화면을 재생하지 않습니다.

## Mempool과 모의 네트워크

세 노드의 대기 거래를 비교합니다. 새 실습은 **수동 전달**로 시작하므로 다른 화면을 보는 동안 자동으로 상태가 같아지지 않습니다. 노드·블록체인에서 **메시지 1개 전달** 버튼으로 A→B, A→C 상태 변화를 직접 관찰합니다. 빠른 시연에는 **메시지 자동 전달**을 켤 수 있습니다. Mempool은 공유 배열이 아닙니다.

대기열의 거래나 블록을 선택하면 실제 출발·도착·종류에 대응하는 주황 경로가 표시됩니다. 선택은 미리보기이며 실제 전달은 항상 대기열의 첫 메시지를 처리합니다. **다음 실제 전달**을 확인하세요. 최근 수신 경로는 승인/거부 문구와 초록/빨강 점선으로 남으며 **이 메시지의 검증 단계 보기**에서 실제 수신 노드의 검사 결과를 확인할 수 있습니다. A뿐 아니라 B·C에서 출발하는 거래와 블록도 같은 방식으로 표시됩니다.

이벤트의 수신과 검증 승인/거부는 서로 다른 단계입니다. 동일 메시지를 다시 받아도 중복 저장하지 않습니다. 한 번에 한 노드만 채굴하며 이전 블록 전달이 끝나야 다음 채굴을 시작할 수 있습니다.

## 채굴

- **한 번 계산하기:** Nonce 하나의 실제 해시를 계산하고 멈춥니다. 이미 성공했다면 바로 블록 검증으로 진행합니다.
- **연속 채굴 시작:** 새 후보를 만들어 반복 계산합니다.
- **천천히 학습 실행:** 약 250ms의 관찰 대기 후 Nonce 하나씩 실제로 계산합니다. 빠른 실행과 같은 해시·PoW 검사를 사용합니다.
- **일시정지 / 계속 채굴:** 같은 후보의 다음 Nonce에서 중지·재개합니다.
- **채굴 중지:** 작업을 끝냅니다. 대기 거래는 보존하고 다음 시작은 새 후보의 Nonce 0부터 탐색합니다.

해시는 Python 백엔드가 계산합니다. 화면이 계산을 요청할 때마다 백엔드가 다음 Nonce들을 실제로 계산해 결과를 돌려주며, 요청이 없으면 계산도 진행하지 않습니다. 그래서 채굴 중인 탭을 다른 탭 뒤에 두면 브라우저가 요청 간격을 늦춰 채굴이 느려질 수 있습니다.

빠른 연속 실행은 일시정지·중지를 바로 처리할 수 있도록 계산을 약 40ms 묶음으로 나눕니다. 화면 해시는 표본이고 시도 횟수는 모든 계산의 합입니다. 두 모드 모두 최근 실제 Nonce·Hash·목표값 통과 여부를 최대 12개 보관합니다. 첫 묶음에서 성공해도 마지막 실패와 성공을 비교할 수 있고, 첫 해시가 성공하면 성공 사례 하나만 표시합니다. 실패 장면을 만들려고 유효 해시를 무시하지 않습니다.

**실제 계산 시간**은 백엔드가 해시를 계산한 구간의 합계이며 일시정지·대기·요청 왕복 시간은 제외합니다. **학습 관찰 대기 시간**은 저속 실행의 계산과 다음 계산 요청 사이의 대기이며 일시정지는 제외합니다. H/s는 실제 계산 시간으로만 계산합니다. 성공 시간은 확률적이므로 어떤 난이도든 한 번의 결과로 성능을 일반화하지 마세요.

난이도 비교는 각 난이도에서 여러 번 새 실습을 시작하여 시도 횟수·시간·H/s를 기록합니다. 기대 시도 횟수는 1:16, 2:256, 3:4,096, 4:65,536입니다. 채굴 시 코인이 새로 생기지 않습니다.

## 블록 탐색과 변조

블록 타일을 선택해 Hash·Previous Hash·거래 목록 해시·Nonce·난이도·후속 블록 수를 확인합니다. 거래 상세에서 입력·출력·서명·공개키를 볼 수 있습니다.

후속 연결까지 보려면 최소 두 개의 일반 블록을 만든 후 블록 #1을 바꾸세요. **해시만 재계산**은 해당 블록의 거래 목록 해시와 헤더 해시만 바꾸며, 전자서명·PoW·다음 블록은 고치지 않습니다. 헤더 시각만 바꾸면 거래 서명은 그대로 유효할 수 있지만 블록 해시와 연결은 달라집니다.

## 문제 해결

| 증상 | 확인·조치 |
|---|---|
| `npm.ps1` 실행 정책 오류 | 명령을 `npm.cmd`로 실행 |
| Node 버전 오류 | `node --version`으로 24.x 확인 후 새 터미널에서 재설치 |
| `uv` 명령을 찾을 수 없음 | uv를 설치한 뒤 새 터미널에서 `uv --version` 확인 |
| `http://127.0.0.1:8000`에 화면 대신 `HTTP_ERROR`·`Not Found`가 표시됨 | 빌드된 화면이 없는 상태. `frontend`에서 `npm.cmd run build` 후 백엔드를 다시 시작. `--api-only`로 실행했다면 그 옵션 없이 실행 |
| 화면을 고쳤는데 이전 화면이 보임 | 백엔드 하나로 실행할 때는 `npm.cmd run build`를 다시 실행하고 새로고침 |
| **백엔드에 연결할 수 없습니다** 안내 | 서버 두 개 방식에서 `backend` 폴더의 `uv run mini-bitcoin-backend`가 실행 중인지, 8000 포트인지 확인한 뒤 다시 시도 |
| **실습을 찾을 수 없습니다** 안내 | 백엔드를 다시 시작했거나 오래된 실습이 정리된 경우. **초기화 ↺** 후 새 실습 시작 |
| 백엔드 시작 시 포트 사용 중 오류 | 8000 포트의 다른 프로그램을 종료하거나 `uv run mini-bitcoin-backend --port 8001`로 실행해 그 주소를 열기. 서버 두 개 방식이라면 화면 개발 서버를 시작하기 전에 `$env:MINI_BITCOIN_API_URL = 'http://127.0.0.1:8001'` 설정 |
| 페이지가 열리지 않음 | 터미널 서버 유지 여부와 실제 출력 포트 확인 |
| 화면 개발 서버의 포트를 사용 중 | Vite가 안내한 다른 포트 사용 또는 원래 서버 종료 |
| 채굴이 갑자기 느려짐 | 채굴 화면의 탭이 다른 탭이나 창 뒤에 있는지 확인. 보이는 상태로 두기 |
| 채굴 버튼 비활성 | 선택 노드 Mempool에 유효 거래가 있는지, 이전 블록 전달이 끝났는지 확인 |
| 잔액은 있는데 송금 불가 | 해당 UTXO가 대기 거래에 예약되어 있는지 확인 |
| 노드 잔액 불일치 | 자동 전달 여부와 메시지 대기열 확인 |
| 지갑이 사라짐 | 새로고침·초기화·백엔드 재시작의 의도된 동작. 예제 시작으로 재실습 |
| 테마가 운영체제와 다름 | 화면 테마를 시스템으로 선택. 라이트·다크 직접 선택은 시스템 설정보다 우선 |
| E2E 브라우저 없음 | Chrome·Edge 설치 또는 설치된 브라우저의 `--project`만 선택 |
| E2E 포트 충돌 | 4173·8173에서 다른 서비스나 이전 테스트 서버가 동작하는지 확인. `test:e2e:single`은 4173에 남은 서버가 있으면 시작하지 않음 |
| 빌드 파일 더블클릭 시 오류 | `file://`로는 실행할 수 없음. 백엔드를 실행해 `http://127.0.0.1:8000`으로 열기 |

최초 설치에만 인터넷 연결이 필요합니다. 화면과 백엔드는 모두 이 PC의 `127.0.0.1`에서 실행되므로 외부 서버 장애가 실습의 거래·서명·채굴에 영향을 주지 않습니다.
