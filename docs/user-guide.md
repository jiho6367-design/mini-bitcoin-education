# 사용 안내

## 실행과 초기화

저장소에서 `npm.cmd ci` → `npm.cmd run dev` 후 표시된 로컬 주소를 엽니다. Node.js 24.x를 사용합니다. 새로고침·브라우저 닫기는 데이터 삭제와 같습니다. 저장·복원 기능은 없습니다.

시작 화면에서 난이도를 고르고 **예제 실습 시작** 또는 **직접 시작: Alice 지갑 생성 → Bob 지갑 생성 → 생성한 지갑으로 시작**을 사용합니다. 최초 두 지갑 이름은 설명을 위해 Alice와 Bob으로 고정합니다. 추가 지갑에는 코인을 배정하지 않습니다.

실습 중 난이도를 바꾸려면 시작 화면의 **난이도를 바꿔 새 실습**을 누르고 초기화를 확인합니다. 이전 실습을 보존하면서 난이도만 바꾸지는 않습니다.

## 지갑·거래

상단 관찰 노드를 선택하면 해당 노드가 알고 있는 잔액과 UTXO를 보여줍니다. 공개키·개인키는 펼쳐 보기에서 확인합니다. 실제 개인키를 입력하거나 복구하는 기능은 없습니다.

보내는 지갑·받는 지갑·정수 송금액을 고르고 **1. 거래 작성 → 2. 전자서명 → 3. 검증·전파**를 누릅니다. 작성은 코인을 옮기지 않고, 서명도 블록 기록을 의미하지 않습니다. 검증 후 Mempool에 들어가며 채굴·블록 검증 후 확정 UTXO가 바뀝니다.

Alice의 단일 100 UTXO로 30을 송금하면 Mempool 대기 중에는 확정 잔액 100, 송금 가능 0입니다. 100 전체가 입력으로 예약되기 때문입니다. 블록 포함 후 거스름돈 70을 사용할 수 있습니다. 이는 30만 숫자로 차감하는 계좌 방식과 다릅니다.

화면·관찰 노드를 바꾸면 작성 중인 폼은 초기화되지만 제출된 거래는 유지됩니다. 서명 원문·해시·서명·거래 ID는 상세 보기에서 비교합니다.

## 실패 실험

- **잔액 부족:** 101을 입력하고 거래 작성을 누릅니다. 만들 수 없는 이유를 표시합니다.
- **잘못된 서명:** 거래를 작성·서명한 후 전용 실험 버튼을 누릅니다. 서명만 잘못된 사본을 제출합니다.
- **이중 지출:** 유효 거래가 해당 노드 Mempool에 있을 때 전용 실험 버튼을 누릅니다. 같은 입력을 사용하는 별도 유효 서명 거래가 거부됩니다.
- **잘못된 PoW 블록:** 대기 거래가 있을 때 노드·블록체인의 전용 수신 실험 버튼을 누릅니다. 헤더 해시는 일치하지만 목표값을 만족하지 않는 블록을 수신 노드가 거부합니다.
- **변조:** 거래가 담긴 블록을 채굴한 뒤 변조 실험에서 금액 또는 헤더 시각을 바꿉니다. 첫 실패 위치와 각 관계의 상태를 확인합니다.

실패 실험은 실제 데이터 검증을 수행하며 미리 정한 성공·실패 화면을 재생하지 않습니다.

## Mempool과 모의 네트워크

세 노드의 대기 거래를 비교합니다. 노드·블록체인에서 자동 전달을 끄면 **메시지 1개 전달** 버튼으로 A→B, A→C 상태 변화를 직접 관찰할 수 있습니다. Mempool은 공유 배열이 아닙니다.

이벤트의 수신과 검증 승인/거부는 서로 다른 단계입니다. 동일 메시지를 다시 받아도 중복 저장하지 않습니다. 한 번에 한 노드만 채굴하며 이전 블록 전달이 끝나야 다음 채굴을 시작할 수 있습니다.

## 채굴

- **한 번 계산하기:** Nonce 하나의 실제 해시를 계산하고 멈춥니다. 이미 성공했다면 바로 블록 검증으로 진행합니다.
- **연속 채굴 시작:** 새 후보를 만들어 반복 계산합니다.
- **일시정지 / 계속 채굴:** 같은 후보의 다음 Nonce에서 중지·재개합니다.
- **채굴 중지:** 작업을 끝냅니다. 대기 거래는 보존하고 다음 시작은 새 후보의 Nonce 0부터 탐색합니다.

연속 실행은 화면 응답성을 위해 계산을 나눕니다. 화면 해시는 표본이고 시도 횟수는 모든 계산의 합입니다. 시간은 계산 구간의 합이며 일시정지·표시 대기 시간은 제외합니다. 성공 시간은 확률적이므로 어떤 난이도든 한 번의 결과로 성능을 일반화하지 마세요.

난이도 비교는 각 난이도에서 여러 번 새 실습을 시작하여 시도 횟수·시간·H/s를 기록합니다. 기대 시도 횟수는 1:16, 2:256, 3:4,096, 4:65,536입니다. 채굴 시 코인이 새로 생기지 않습니다.

## 블록 탐색과 변조

블록 타일을 선택해 Hash·Previous Hash·거래 목록 해시·Nonce·난이도·후속 블록 수를 확인합니다. 거래 상세에서 입력·출력·서명·공개키를 볼 수 있습니다.

후속 연결까지 보려면 최소 두 개의 일반 블록을 만든 후 블록 #1을 바꾸세요. **해시만 재계산**은 해당 블록의 거래 목록 해시와 헤더 해시만 바꾸며, 전자서명·PoW·다음 블록은 고치지 않습니다. 헤더 시각만 바꾸면 거래 서명은 그대로 유효할 수 있지만 블록 해시와 연결은 달라집니다.

## 문제 해결

| 증상 | 확인·조치 |
|---|---|
| `npm.ps1` 실행 정책 오류 | 명령을 `npm.cmd`로 실행 |
| Node 버전 오류 | `node --version`으로 24.x 확인 후 새 터미널에서 재설치 |
| 페이지가 열리지 않음 | 터미널 서버 유지 여부와 실제 출력 포트 확인 |
| 기존 포트를 사용 중 | Vite가 안내한 다른 포트 사용 또는 원래 서버 종료 |
| 채굴 버튼 비활성 | 선택 노드 Mempool에 유효 거래가 있는지, 이전 블록 전달이 끝났는지 확인 |
| 잔액은 있는데 송금 불가 | 해당 UTXO가 대기 거래에 예약되어 있는지 확인 |
| 노드 잔액 불일치 | 자동 전달 여부와 메시지 대기열 확인 |
| 지갑이 사라짐 | 새로고침·초기화의 의도된 동작. 예제 시작으로 재실습 |
| E2E 브라우저 없음 | Chrome·Edge 설치 또는 설치된 브라우저의 `--project`만 선택 |
| E2E 포트 충돌 | 4173에서 다른 서비스가 동작하는지 확인 |
| 빌드 파일 더블클릭 시 오류 | `npm.cmd run preview`로 로컬 HTTP에서 열기 |

최초 설치에만 인터넷 연결이 필요합니다. 외부 서버 장애가 실습의 거래·서명·채굴에 영향을 주지 않습니다.
