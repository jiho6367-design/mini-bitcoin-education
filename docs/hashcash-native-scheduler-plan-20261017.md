# 전체 C 관리 경로의 사전 실험 계획

기준선 `3d9091a048aa34139682f4a8bf190a20004d0e30`의 gpu/cpu/hybrid/server 원본을
`work/native-scheduler-baseline/`에 보존한다. 개인 DB와 다른 작업 폴더는 사용하지 않는다.

가설: CPU 해시 루프뿐 아니라 persistent CPU worker, 범위 배정, 결과 수집, GPU launch와
readback까지 C로 옮기면 Python의 배치별 관리가 사라져 CPU 추가 기여가 비용을 이길 수 있다.
같은 생성 CUDA 커널·geometry·64M GPU 배치를 유지하고 Python은 준비/최종 검증만 수행한다.

유한 후보는 C CPU 1/4/8개 × CPU 배치 64k/250k/1M의 9개다. 대조군은 기존 Python GPU
단독과 C GPU 단독이다. 첫 탐색은 같은 4,294,967,296개 nonce·28B ASCII·난이도 8·시작
1,000,000,000을 전부 처리해 7회 교대한다. 워커·컴파일 준비는 제외하되 별도 기록한다.
GPU 장치는 루트 담당자만 실행하고 다른 GPU/고부하 CPU 실험과 겹치지 않게 한다.

유망 후보가 있으면 새 13회로 두 대조군과 비교한다. 최고 후보가 변동 안에 있으면 개선
확정으로 쓰지 않는다. CPU 기여는 C GPU 단독과의 차이, C 관리 이전 효과는 Python GPU
단독과 C GPU 단독의 차이로 구분한다. 한국어와 20자리 nonce도 확인한다.

공정한 주 비교에서 유한 종료점을 이용한 CPU tail guard는 0으로 둔다. CPU 자체의
끝 꼬리·실제 proof 탐색과 초기화 비용·취소를 별도 확인한다. 단일 ctypes 호출 안에서
Python callback이 실행되지 않아야 한다. CUDA event와 QPC 타임라인·정확한 완료 범위를
기록하고 중복·누락/해시 오류가 있으면 속도 결과를 채택하지 않는다.

실패 구간 CPU 재시도, UINT64_MAX, 자리수 경계, 공백·개행·UTF8, 취소·재시작, proof 경쟁,
늦은 정리 오류를 검사한다. 제작과 독립 검증을 나누고 소스·빌드·원시 표본을 보존한다.

실제 기본 메시지 proof 기능검사 한 번에서 C동시 모드의 반환이 C GPU보다 조금 늦어,
준비비용과 변동을 구분하기 위한 추가 확인을 사전에 고정한다: 기본 메시지·난이도8·같은
시작/유한영역에서 Python GPU/C GPU/C4+GPU의 실제 탐색을 13회 교대한다. 과거 proof를
재사용하지 않고 새로 계산한다. 이 한 메시지의 반복과 모든 메시지의 발견시간 분포를
구분한다. 이 확인 뒤에는 새 성능 후보를 추가하지 않는다.
