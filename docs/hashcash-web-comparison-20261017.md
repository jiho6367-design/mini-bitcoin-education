## 측정 조건과 시계

- 기준선: `281799f79f01990cf52fba77238977a3feb327b4`. C/CUDA 계산 코드는 유지하고 서버의 첫 proof 시각과 첫 자릿수 준비 계측을 추가했다.
- Intel Core Ultra 7 356H, 논리 CPU 16개, NVIDIA GeForce RTX 5070 Laptop GPU, Windows, NVIDIA 드라이버 591.74, 프로젝트 Python 3.13 가상환경, 설치된 Edge headless.
- 웹 폼에서 `gpu` / `native`를 선택하고 실제 버튼을 눌렀다. 입력 CPU 수는 양쪽 모두 4이며 GPU 단독은 CPU 작업을 실행하지 않는다. GPU 배치는 난이도 8·64에서 67108864개다.
- 각 입력·모드 준비 실행 1회 후 **13쌍**을 GPU→C / C→GPU 순서로 교대했다. 네 입력 합계 정식 실행 104개와 준비 실행 8개를 전부 보관했다.
- 정식 측정 중에는 화면의 기존 350ms 상태 응답만 관찰했다. 추가 HTTP 상태 조회는 없으며, 최종 검증 요청·해시 재검산·스크린샷·nvidia-smi는 측정 구간 밖에서 수행했다.
- 5187 실습 서버와 사용자 SQLite는 사용하지 않았다. 5188/9188 및 첫 사용용 5190/9190·5191/9191, 별도 임시 기록 폴더를 이용했다. GPU 실행은 주 담당자만 순차 수행했다. Windows DWM·Edge 그래픽 활동은 유지했고, 전력·드라이버 설정을 바꾸지 않았다. 표본별 전후 GPU 상태를 남겼으며 전 실행 구간의 전력·CPU 사용률을 연속 측정한 것은 아니다.

시간은 다음처럼 구분했다.

1. **준비** = `startupElapsed + searchPreparationElapsed`. 초기화·자체 검증·초기 준비에 더해 GPU 단독이 새 자릿수를 처음 구성·컴파일하는 비용을 포함한다. C는 1~20자리 함수를 시작 전에 모두 준비한다. 반복 배치의 기존 compile 호출과 Python 관리 비용은 탐색 시간에 남긴다.
2. **준비 제외 해답 수신** = `proofSearchElapsed`. 계산을 시작해 배치 해답을 독립 검증해 받은 순간까지이며 커널 내부 원자 연산의 순간은 아니다. C의 `QPC begin + first_proof_seconds`를 사용해 100ms 서버 감시 지연을 제외한다. 이 PC의 Python perf_counter와 C는 같은 QPC 시계다.
3. **준비 포함 첫 해답** = `proofElapsed`. 작업 생성부터 첫 독립 검증 해답 수신까지다.
4. **서버 작업 종료** = `elapsed`. C의 진행 중 CPU 배치 정리·추적 분석·해제까지 포함한다. SQLite 저장 전에 고정되며, 화면의 저장 완료는 그 이후다.
5. **화면 표시**는 실제 클릭 이벤트부터 결과 DOM이 나타날 때까지 별도로 측정했다. 350ms 화면 갱신과 브라우저 처리 지연을 포함한다.

## 짧은 한글 탐색에서 이득이 사라진 이유

기본 난이도 8은 양쪽 모두 nonce `3243428010`, 한글은 양쪽 모두 `1415603441`을 찾았다. 같은 해답이 나온 것 자체는 합격 조건으로 사용하지 않았다.

| 실제 완료 작업의 중앙값 | GPU 단독 GPU 계산 | C의 GPU 계산 | C의 CPU 계산 |
| --- | ---: | ---: | ---: |
| 기본 난이도 8 | 2281701376 = 34배치 | 2214592512 = 33배치 | 46848000 |
| 한글 난이도 8 | 469762048 = 7배치 | 469762048 = 7배치 | 11008000 |

관측된 사실은 기본 입력에서는 C가 GPU 배치 하나를 줄였고, 한글 입력에서는 CPU가 약 1101만 개를 계산해도 GPU 배치 수가 줄지 않았다는 점이다. 한글의 총 완료 계산량은 오히려 약 2.34% 많았다. **이 배치 경계와 추가 준비·정리 비용이 짧은 탐색의 이득을 상쇄한 것으로 추정한다.** 각 비용을 독립 조작한 인과 실험은 아니므로 어느 요소가 몇 ms를 차지한다고 단정하지 않는다.

## 화면 표시와 관찰 부하 대조

기본 난이도 8의 실제 화면 결과 표시 중앙값은 GPU **662.2ms**, C **661.8ms**였다. 서버의 약 17ms 탐색 차이가 350ms 화면 갱신에 가려져, 표시 시간의 뚜렷한 개선은 확인하지 못했다.

처음에는 보조 50ms HTTP 조회를 넣어 같은 13쌍·네 입력을 측정했다. 독립 검토에서 Python 관리 부하를 늘릴 가능성이 지적되어 해당 112개를 대조 자료로 보존하고, 정식 비교는 추가 조회 없이 다시 수행했다. 대조의 준비 제외 중앙값 변화는 기본 난이도 8 −4.95%, 한글 −1.88%, 고정량 −2.81%였다. 정식 조건의 한글 결과는 +1.92%로 방향도 바뀌었으므로 작은 차이를 관찰 조건과 무관한 일반 성능 주장으로 확대하지 않는다. 대조 버전은 GPU 최초 compile 호출만 준비에 집계했고 정식 버전은 최초 소스 구성까지 포함하며, 두 소스 버전을 함께 보존했다.
