# 검토보고서 반영 기록

2026-09-30. 사용자가 제공한 `mini-bitcoin-education_검토보고서.md`는 코드 확인을 위한 검토 자료로 사용했다. 문서 속 구현 요청 예시는 실행 지시로 취급하지 않았으며, 사용자의 별도 “지적 사항 검증 후 코드·문서 수정” 요청에 따라 아래 작업을 수행했다.

## 확인과 반영

| 항목 | 현재 코드에서 확인한 내용 | 반영 |
|---|---|---|
| F-01 | 기존 상단 계산은 검증 단계 2를 반환하지 않았고 작성·서명 로컬 상태를 알지 못했다. 기존 체인 높이로 새 거래도 완료처럼 표시했다. | 작성 폼과 관찰 거래를 실습 제어기에 보관. 작성·서명·검증 성공/실패·결과 관찰·Mempool·해당 거래의 채굴·노드별 블록 포함을 추적. 새 작성은 기존 완료 표시를 끊는다. |
| F-02 | 성공 이중 지출 검사에도 이미 사용 중이라는 실패 설명을 표시했다. | 거래 검증 9단계 모두 성공/실패 문구를 분리. 금액 보존 성공은 실제 입력·출력 합계도 표시. 규칙·오류코드 유지. |
| F-03 | 큐가 있으면 도식 점을 고정 좌표에 그렸다. | 실제 from/to/kind에 대응하는 경로와 화살표. 큐 선택은 미리보기이며 다음 실제 FIFO 전달을 별도 표시. 실제 최근 수신·검증 결과 표시. |
| G-01 | 기본 자동 전달이 다른 화면에서도 진행되어 상태 차이를 놓칠 수 있었다. | 새 실습은 수동 전달. 자동 700ms 전달과 기존 자유 실습은 유지. |
| G-02 | 첫 채굴 묶음에서 found면 중간 progress가 없어 실패 표본을 볼 수 없었다. | 약 250ms마다 하나씩 실제 계산하는 학습 모드 추가. 두 모드 모두 최근 12개의 실제 Nonce·Hash·판정 보관. 첫 성공도 그대로 인정. 계산 시간과 관찰 대기 시간 분리. |
| G-03 | 입력 전체 예약과 거스름돈 생성 관계가 여러 상세 정보에 흩어져 있었다. | 입력 원본과 관찰 노드의 현재 상태로 예약→소비, 작성 출력→대기→블록 포함을 연결한 도식 추가. |

검증 결과 관찰은 UI 단계다. 유효 거래의 실제 검증·Mempool 등록은 즉시 처리한다. 노드의 독립 상태나 UTXO·서명·블록 수락 규칙을 변경하지 않았다.

## 이번에 확장하지 않은 제안

G-04의 별도 가이드 모드·퀴즈, G-05의 난이도별 누적 비교 실험은 보고서에서도 후순위 새 제안으로 구분했다. 이번 수정에서는 현재 거래 추적과 관찰 안내까지만 보완하고, 별도 채점·비교 실험 화면은 추가하지 않았다. 난이도는 실습별 고정, 반복 비교는 새 실습의 실제 통계를 직접 기록하는 기존 방법을 유지한다. 사용자 대상 교육 효과 연구를 수행했다고 주장하지 않는다.

## 검증 근거

- `src/core/transaction-feedback.test.ts`: 정상 9단계와 실패 코드별 문구 일치.
- `src/ui/learning.test.ts`: 검증 관찰·실패 미완료·선택 거래 포함·전체 노드 수락·두 번째 거래·결과 보존.
- `src/ui/network.test.ts`: 여섯 방향 SVG 경로·큐 선택과 FIFO 구분·수신 승인/거부·종류.
- `tests/learning.spec.ts`: 위 상태를 실제 Chrome/Edge UI에서 조작, UTXO 예약/소비와 새 출력 확인, 저속 실행·중지.
- `tests/worker.spec.ts`: 실제 저속 계산과 pause/stop/stale 작업, 첫 묶음 표본 제한, Nonce 0 성공.

실제로 실행한 결과와 실패 후 재검증 이력은 [테스트 기록](test-results.md)에 기재한다.
