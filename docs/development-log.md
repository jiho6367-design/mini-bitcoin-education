## 유지한 범위

별도 서버·DB·실습 저장 복원·Mainnet·실제 금전 거래·동시 채굴·체인 분기 복구를 추가하지 않았다. 실제 Bitcoin과의 차이는 앱과 문서에서 확인할 수 있다. 시연 영상 촬영은 별도 작업으로 유지한다.

위 범위는 1.1.0까지의 기록이다. 2.0.0에서 별도 서버(Python 백엔드)를 추가했고 나머지 범위는 그대로 유지한다. 아래 2.0.0 기록을 참고한다.

## 2026-10-01 — 2.0.0 화면과 Python 백엔드 분리

- 사용자 요청으로 프로젝트를 `frontend/`(React 화면)와 `backend/`(Python·FastAPI, uv로 관리)로 나누었다. 지갑·개인키 보관·서명·검증·모의 노드·채굴·실패 실험을 모두 백엔드로 옮기고, 브라우저의 TypeScript 핵심 로직과 Web Worker를 삭제했다. 같은 규칙을 두 언어로 중복 구현하지 않는다.
- 실행 방법이 서버 두 개와 uv를 필요로 하도록 바뀌고 저장소 구조도 달라졌으므로 기존 사용 방식과 호환되지 않는다. 화면의 실습 절차는 유지했지만 1.1.0에서 2.0.0으로 올리는 MAJOR 변경이다.
- 데이터 형식(서명 원문·거래 ID·거래 목록 해시·블록 해시·주소)은 그대로 유지했다. TypeScript 코드를 삭제하기 전에 고정 키·실습 ID·시각으로 기준값을 기록하고, Python 구현이 주소·서명·거래 ID·블록 해시와 세 블록 시나리오의 단계별 검증 결과를 그대로 재현하는지 검사한다. 기준값과 생성기 보관본은 `backend/tests/vectors/`에 둔다.
- 서명은 `cryptography` 라이브러리로 구현했다. 기존 noble 구현과 같은 값을 내도록 결정적 서명(RFC 6979)을 사용하고, s를 작은 쪽 값으로 고정하며, 검증 시 큰 쪽 s를 거부한다.
- 채굴은 백엔드가 계산하되 스레드를 두지 않았다. 화면이 계산을 요청할 때마다 다음 묶음을 계산한다. 서버에 백그라운드 작업이 없어 탭을 닫으면 계산이 멈추고, 시간을 주입한 테스트로 단계·일시정지·시간 집계를 결정적으로 검사할 수 있다. 화면 없이 채굴이 진행되지 않고 보이지 않는 탭에서 느려지는 점은 한계로 기록했다.
- 개인키는 실습 상태 응답에 넣지 않고 전용 조회 경로로만 보낸다. 실습 상태·메시지·이벤트·화면 테스트 예시 데이터에 개인키가 없음을 테스트로 확인한다.
- 화면은 같은 출처의 `/api`만 호출하고 Vite 서버가 백엔드로 전달한다. 외부 요청을 차단하는 기존 브라우저 테스트를 수정 없이 통과한다.
- 화면의 조작은 누른 순서대로 한 번에 하나씩 요청한다. 초기화 뒤에 도착한 이전 실습·이전 채굴 작업의 응답은 실습 ID·작업 ID·순번으로 무시한다.
- 기존 학습 흐름 브라우저 테스트 9개(`learning.spec.ts`)는 수정하지 않고 그대로 통과시키는 것을 기준으로 삼았다. Web Worker를 직접 다루던 브라우저 테스트 5개는 백엔드의 채굴 작업 테스트로 옮겼고, 채굴 화면·연결 실패·사라진 실습·개인키 조회를 다루는 브라우저 테스트를 새로 추가했다.
- 작업 중 확인한 문제:
  - 기준값 생성기가 "정상 거래" 판정을 시나리오가 코인을 소비한 뒤에 기록해 `MISSING_UTXO`가 저장되었다. Python 구현이 아니라 생성기의 오류였고, 판정을 소비 전에 기록하도록 고쳐 다시 생성했다.
  - 빈 실습 보관소가 거짓으로 평가되어, 테스트가 넘겨준 보관소 대신 새 보관소가 만들어졌다. 정리(eviction) 테스트에서 드러났고 `None` 여부를 직접 확인하도록 고쳤다.
  - 난이도 1에서는 첫 Nonce가 1/16 확률로 성공한다. 이를 고려하지 않은 API 테스트가 가끔 실패해, 첫 계산이 실패한 실습을 골라 검사하도록 테스트를 고쳤다. 이후 백엔드 전체 테스트를 25회 연속 실행해 모두 통과했다.
  - 같은 거래라도 JSON의 필드 순서가 다르면 다른 지문이 되어 중복으로 알아보지 못할 수 있었다. 형식 검사를 통과한 값을 기준으로 지문을 만들도록 했다.
  - 새 브라우저 테스트의 요청 가로채기 패턴이 화면 소스 경로(`/src/api/…`)까지 잡았다. 경로가 `/api/`로 시작하는 요청만 고르도록 테스트를 고쳤다.
  - Starlette 테스트 클라이언트가 `httpx` 사용을 더 이상 권장하지 않아 개발 의존성을 `httpx2`로 바꿨다.
- 실제 최종 검사 명령과 결과는 [테스트 기록](test-results.md)에 둔다.

## 2026-10-01 — 2.1.0 Python 백엔드 하나로 실행

- 2.0.0은 실행에 서버 두 개가 필요했다. 사용자 요청으로 백엔드가 빌드된 화면도 함께 제공하게 하여, 실행 중에는 Python 서버 하나만 있으면 되도록 했다.
- 화면을 Python으로 다시 만드는 방법(React 제거)도 검토했으나, 사용자 선택에 따라 React 화면과 그 테스트를 유지하고 백엔드가 빌드 결과를 제공하는 방식으로 정했다. 빌드 결과를 저장소에 넣지 않는 것도 사용자 선택이다. 따라서 화면 빌드에는 PC마다 Node.js가 한 번 필요하다.
- 기존 서버 두 개 방식과 실습 절차가 그대로 동작하는 기능 추가이므로 2.0.0에서 2.1.0으로 올리는 MINOR 변경이다.
- 백엔드는 `/api` 경로를 먼저 찾고 나머지 경로만 화면 폴더에서 찾는다. 화면 폴더에 `index.html`이 없으면 API만 제공하고 빌드 방법을 알린다. 다시 빌드한 화면이 바로 보이도록 HTML은 브라우저가 매번 확인하게 했다.
- 화면의 실습 코드는 수정하지 않았다. 화면이 처음부터 같은 출처의 `/api`만 호출하도록 만들어져 있어, 화면과 API가 한 서버에 있어도 그대로 동작한다.
- 브라우저 시나리오는 파일을 바꾸지 않고 설정만 하나 더 두어, 화면 개발 서버 없이 백엔드 하나만 실행한 상태에서도 같은 시나리오를 실행한다. 서버 두 개 방식의 E2E에서는 백엔드를 `--api-only`로 실행해 화면이 개발 서버에서 오는 것을 분명히 했다.
- 백엔드 하나로 실행하자 요청 기록에 `GET /favicon.ico 404`가 보였다. 페이지에 아이콘 지정이 없어 브라우저가 기본 경로를 요청한 것이다. 화면 개발 서버는 요청 기록을 출력하지 않아 그동안 눈에 띄지 않았다. `frontend/public/favicon.svg`를 추가하고 `index.html`에서 지정해 해결했다. 화면 소스의 변경은 이 두 파일뿐이다.
- 한계: 화면 소스를 바꾸고 다시 빌드하지 않으면 이전 화면이 제공된다. 백엔드 하나로 실행할 때는 화면 수정이 자동으로 반영되지 않는다.
- 실제 최종 검사 명령과 결과는 [테스트 기록](test-results.md)에 둔다.

## 앞으로의 버전 관리 규칙

버전은 `MAJOR.MINOR.PATCH` 형식으로 관리하며 **검증과 문서 갱신이 끝난 업데이트 단위마다** 올린다. 파일 저장이나 개별 커밋마다 버전을 올리지 않는다. 한 업데이트에 여러 변경이 있으면 그중 가장 큰 호환성 영향을 기준으로 결정한다.

| 구분 | 변경 기준 | 예 |
|---|---|---|
| PATCH | 기존 사용 방식과 기능을 유지하는 작은 오류·문구 수정 | 잘못된 설명 문구, 표시 오류 수정 |
| MINOR | 기존 사용 방식과 호환되는 기능 추가 | 테마 선택, 추가 관찰 기능 |
| MAJOR | 기존 사용 방식과 호환되지 않는 큰 변경 | 기존 실습 절차·데이터 규칙을 호환되지 않게 변경 |

1. 완료된 변경 범위를 검토하고 `frontend/package.json`의 버전을 정한다.
2. `frontend/package-lock.json`의 최상위 버전과 루트 프로젝트 버전, `backend/pyproject.toml`의 버전을 같은 값으로 맞추고 `uv lock`으로 `backend/uv.lock`을 갱신한다. 버전 변경만을 위해 의존성을 업그레이드하지 않는다.
3. 앱이 `frontend/package.json` 값을 자동 표시하고 백엔드의 `/api/health`가 같은 버전을 알리는지 확인한다. 실제 수행한 검사 결과를 테스트 기록에 남긴다. 일부 재검사 결과를 전체 검사 결과로 기록하지 않는다.
4. [CHANGELOG](../CHANGELOG.md)에 해당 버전·날짜·주요 변경사항을 기록한다. 과거에 존재하지 않았던 출시 이력은 만들지 않는다.
