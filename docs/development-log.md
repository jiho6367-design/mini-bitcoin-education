# 개발 기록

## 2026-09-30 — 최초 구현과 실행 검증

- 저장소의 초기 README·문서 및 수행계획서 PDF를 확인하고, 기존 자료를 보존한 상태에서 구현했다.
- 승인된 React·TypeScript·Vite, secp256k1 ECDSA, UTXO, 3개 모의 노드, Web Worker 설계를 적용했다.
- 핵심 로직과 화면을 분리하고 입력·출력 합계 보존, 독립 노드 상태, 원자적 블록 반영을 먼저 구현했다.
- 서명 실패, 잔액 부족, 이중 지출, 잘못된 PoW 블록 수신, 과거 블록 변조 실험을 연결했다.
- Worker 단계·일시정지·재개·중지, 오래된 jobId 무시와 초기화 이후 지연 결과 회귀 테스트를 추가했다.
- Chrome·Edge 자동 브라우저 검사에서 Windows 첫 실행과 긴 시나리오가 30초 제한을 초과했다. 실패 로그에서 시작·캡처 대기 시간을 확인하고 총 테스트 제한을 90초로 조정했다. 채굴의 성공 시간을 고정한다는 의미는 아니다.
- 초기 전체 페이지 캡처에서 스크롤된 고정 사이드바 위치가 어긋나, 캡처 전 스크롤을 상단으로 맞췄다. 실제 앱도 화면 전환 시 상단으로 이동하도록 개선했다.
- 다른 노드의 자동 검증이 선택 노드의 오류를 덮어쓰지 않게 최근 검증 결과를 노드별로 보관하고 회귀 테스트를 추가했다.
- 코드를 읽기 쉬운 형식으로 정리했다. 최종 실행·검증 상태는 [테스트 기록](test-results.md)에 별도 기재한다.

## 유지한 범위

별도 서버·DB·실습 저장 복원·Mainnet·실제 금전 거래·동시 채굴·체인 분기 복구를 추가하지 않았다. 실제 Bitcoin과의 차이는 앱과 문서에서 확인할 수 있다. 시연 영상 촬영은 별도 작업으로 유지한다.

## 2026-09-30 — 검토보고서에 따른 교육 화면 보완

- 보고서의 F-01~03을 현재 코드에서 확인한 뒤 사용자 승인으로 수정했다. 원장 규칙을 유지하고 선택 거래 상태를 화면 이동 후에도 보관한다.
- 검증 9단계의 성공·실패 설명을 분리하고, 새 거래와 실패 검증이 이전 완료를 이어받지 않도록 했다.
- 실제 저속 Nonce 계산과 최대 12개 표본, 계산/관찰 대기 시간 분리를 추가했다. 첫 해시의 성공을 허위 실패로 바꾸지 않는다.
- 기본 수동 전달, 실제 메시지 선택 경로와 FIFO 다음 전달, 수신 검증 사본을 연결했다.
- 실제 UTXO 예약·소비와 수신/거스름돈 출력 도식을 추가하고 실행·설계·시연 문서를 갱신했다.
- 별도 퀴즈와 난이도 비교 실험 화면은 후순위 제안으로 남겼다. 상세 처리 범위는 [반영 기록](review-resolution.md)에 둔다.

## 2026-09-30 — 1.1.0 화면 테마와 버전 관리

- 기존 1차 교육 화면 개선과 이번 테마·버전 관리 기능을 묶어 1.0.0에서 1.1.0으로 올린다. 기존 거래·검증·채굴·노드 규칙을 유지하는 기능 추가이므로 MINOR에 해당한다.
- 좌측 하단 설명을 정확히 **학습용 블록체인**으로 변경한다.
- 라이트·다크·시스템 선택을 추가하고 처음에는 시스템을 따른다. 테마 선택값만 저장하고 실습 상태와 Worker 작업은 메모리에 유지한다.
- 배경·글자·입력·버튼·검증 상태·해시·UTXO·노드 SVG를 공통 색상 변수로 관리하여 두 테마에 맞춘다.
- package.json을 버전의 기준으로 삼고 앱이 이 값을 자동 표시하게 한다. package-lock.json 프로젝트 버전을 일치시키며 의존성 버전은 변경하지 않는다.
- 기존 테스트를 유지하고 테마 선택·저장·실습 보존·버전 표시 검사를 추가한다. 실제 최종 검사 명령과 결과는 [테스트 기록](test-results.md)에 둔다.

## 앞으로의 버전 관리 규칙

버전은 `MAJOR.MINOR.PATCH` 형식으로 관리하며 **검증과 문서 갱신이 끝난 업데이트 단위마다** 올린다. 파일 저장이나 개별 커밋마다 버전을 올리지 않는다. 한 업데이트에 여러 변경이 있으면 그중 가장 큰 호환성 영향을 기준으로 결정한다.

| 구분 | 변경 기준 | 예 |
|---|---|---|
| PATCH | 기존 사용 방식과 기능을 유지하는 작은 오류·문구 수정 | 잘못된 설명 문구, 표시 오류 수정 |
| MINOR | 기존 사용 방식과 호환되는 기능 추가 | 테마 선택, 추가 관찰 기능 |
| MAJOR | 기존 사용 방식과 호환되지 않는 큰 변경 | 기존 실습 절차·데이터 규칙을 호환되지 않게 변경 |

1. 완료된 변경 범위를 검토하고 package.json의 버전을 정한다.
2. package-lock.json의 최상위 버전과 루트 프로젝트 버전을 package.json에 맞춘다. 버전 변경만을 위해 의존성을 업그레이드하지 않는다.
3. 앱이 package.json 값을 자동 표시하는지 확인하고 실제 수행한 검사 결과를 테스트 기록에 남긴다. 일부 재검사 결과를 전체 검사 결과로 기록하지 않는다.
4. [CHANGELOG](../CHANGELOG.md)에 해당 버전·날짜·주요 변경사항을 기록한다. 과거에 존재하지 않았던 출시 이력은 만들지 않는다.
