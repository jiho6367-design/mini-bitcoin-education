## 제공 영상과 발표 준비

최신 영상은 기초 → 세 노드 채굴 비교 → 공동 → 넌스 찾기를 실제 마우스·키보드로 조작한 녹화입니다 한국어 클릭 안내 자막을 포함하며 2880×1980·30fps로 제공합니다 앱 화면 아래 별도 자막 공간을 사용하고 정지 대기 구간만 정리했습니다 사진 연결·확대·배속 영상이 아닙니다

앱의 **시작하기 → 시연 영상 보기**에서도 재생할 수 있습니다 영상은 자동 재생되지 않으며 재생이 어려우면 **영상 파일 열기**나 **MP4 다운로드**를 사용합니다 이 대본의 시간은 완성 영상 기준이며, 다시 실습하면 계산·네트워크 시간은 달라집니다

직접 발표할 때는 다음을 준비합니다

1. 공개 링크를 미리 열어 서버 준비가 끝나는지 확인합니다 온라인 실행에 발표 PC의 Python 서버는 필요하지 않습니다
2. 기초는 새 시연 실습 공간, 공동은 **새 실습 만들기**로 별도 방을 준비합니다 팀원이 사용하던 공유 장부를 초기화하지 않습니다
3. 공동 초기 코인은 100, 기초 채굴 난이도는 2로 정하면 아래 잔액 예시를 그대로 설명할 수 있습니다 기초 채굴 보상은 노드 채굴자 지갑으로 받습니다
4. 지갑의 학습용 개인키·운영 비밀코드·DB 접속 정보는 영상이나 발표 화면에 펼치지 않습니다
5. 고정된 성공 시간이나 발견 노드를 약속하지 않습니다 오래 걸리면 설명하면서 기다리거나 새 독립 실습에서 더 낮은 난이도로 진행합니다

## 4분 33초 영상 흐름

| 영상 시간 | 실제 화면·조작 | 짧은 설명 |
| --- | --- | --- |
| 0:00~0:21 | 시작하기의 상단 메뉴와 실습 안내 확인 | 기초·공동·넌스 찾기를 나누어 배우는 블록체인 실습실입니다 |
| 0:21~0:42 | 지갑에서 Alice·Bob 이름 입력 후 각각 생성 | 새 지갑마다 50코인 지급 거래가 대기 중이며 채굴 후 사용할 수 있습니다 |
| 0:42~1:09 | 한 노드 채굴, 난이도 2 적용, 노드 채굴자 보상 지갑 확인 후 연속 실행 | 첫 블록에 두 지급 거래를 넣어 각 지갑의 50코인을 확정합니다 채굴 보상은 별도 지갑에 기록합니다 |
| 1:09~1:24 | 거래·서명에서 Alice → Bob 20 작성·서명·제출 | 작성·서명·노드 검증은 별도 단계입니다 제출한 거래는 아직 채굴을 기다립니다 |
| 1:24~1:48 | 세 노드 비교로 이동, 한 번씩 계산·계속 비교 | A·B·C가 자신의 후보로 실제 해시를 계산합니다 각 노드의 Nonce와 해시를 확인합니다 |
| 1:48~2:01 | 첫 발견과 세 노드 전달 결과 확인 | 이 실행에서는 B가 먼저 발견했고 A·C도 같은 블록을 검증·저장합니다 |
| 2:01~2:16 | 지갑에서 Alice 30/Bob 70 확인 | 20코인 송금이 블록에 확정됐습니다 노드 채굴자 보상은 두 사용자 잔액과 구분합니다 |
| 2:16~2:34 | 공동 실습 → 새 실습 만들기, 별명·초기 100 입력 | 기존 팀 장부와 다른 새 방에서 혼자 실습합니다 |
| 2:34~3:04 | 쉬운 실습에서 팀 A → 자동 전달 → 송금 10·수수료 1 작성·서명·전송 → 단일 채굴 | A 하나만 맡아도 B·C 노드가 거래와 블록을 검증하므로 세 사람이 모일 필요가 없습니다 |
| 3:04~3:23 | 결과와 팀 A89/B110/C100 확인 | 100 입력 중 10 송금·1 수수료를 빼고 A의 거스름돈은 89입니다 가이드는 실제 완료 6/6을 표시합니다 |
| 3:23~3:35 | 지금 저장, 새로고침 후 같은 방 기록 확인 | 같은 링크에서 저장 장부를 이어갑니다 새로고침과 새 실습 생성은 다른 동작입니다 |
| 3:35~4:24 | 넌스 찾기 → CPU·난이도 3 → 탐색 시작 → 해시 다시 검증 | 메시지 뒤 숫자를 바꿔 실제 SHA-256을 계산하고 목표의 0 개수를 만족하는지 독립 재계산합니다 |
| 4:24~4:33 | 새로고침 후 찾은 기록 확인, 접속 주소 안내 | 넌스 결과는 같은 브라우저에 남으며 공동 서버 장부와 별도로 보관됩니다 |

영상의 예시 값은 기초 Alice 30/Bob 70, 공동 A89/B110/C100, 넌스 3055·계산 3056회입니다 해당 넌스 결과는 녹화 당시 메시지와 시작 0의 결과이며 다른 메시지나 연산 방식에서 같은 값을 기대하지 않습니다 GPU 배치는 발견 넌스 이후의 계산을 더 완료할 수 있습니다

## 영상 밖에서 추가로 보여줄 수 있는 검증

변조·동기화는 제공된 4분 33초 영상의 필수 동선에 포함하지 않았습니다 시간이 있으면 별도 기초 시연 실습에서 다음을 진행합니다

1. 정상 A를 남기고 **관찰 노드 B → 블록·변조**로 이동합니다
2. 서명된 송금 거래를 고르고 금액을 바꾼 뒤 검증 실패 이유를 확인합니다 서명이 없는 거래 #0의 채굴 보상과 구분합니다
3. Merkle·해시를 다시 계산하거나 재채굴해도 원래 송금 서명이 유효해지는 것은 아님을 설명합니다
4. **다른 노드와 동기화**로 정상 체인을 복구하고 검증 결과를 비교합니다

기초의 일반 변조는 선택 노드의 체인을 변경합니다 재채굴은 복사본에서 진행하므로 완료 전 취소하면 원래 체인을 유지합니다 모든 변조가 원본과 무관한 사본만 바꾼다고 설명하지 않습니다

## 예상 질문

**PC를 꺼도 팀원이 접속하고 기록을 이어갈 수 있나요**

앱은 사용자 PC가 아닌 Render에서 제공하고 기초·공동 기록은 Neon에 저장합니다 서버 재시작 뒤 같은 공동 링크로 이어갑니다 무료 서비스는 준비 시간·사용 한도·일시 중단이 있을 수 있습니다

**교사가 들어와 있어야 하나요**

일반 팀 실습에는 필요하지 않습니다 별명으로 입장하고 A/B/C 역할을 맡아 진행합니다 기존 교사용 모드는 별도로 유지합니다

**처음 코인은 고정인가요 잔액도 고정인가요**

공동 기본 실습은 각 팀 100으로 시작하지만 새 실습 생성 때 초기 금액을 선택할 수 있습니다 초기 배정은 한 번이며 현재 잔액은 송금·수수료에 따라 변합니다 기초는 새 지갑마다 50 지급 거래를 먼저 채굴하는 다른 모델입니다

**100이 있는데 왜 사용 가능은 0인가요**

공동 UTXO의 100 입력 전체가 대기 거래에 예약됐기 때문입니다 예시의 송금 10·수수료 1이 블록에 포함되면 거스름돈 89를 쓸 수 있습니다 다시 입장해도 코인을 추가 지급하지 않습니다

**기초와 공동 실습의 채굴 보상은 같나요**

기초는 선택 지갑에 10코인을 기록합니다 공동 UTXO는 별도 보상 지갑과 수수료·보상 성숙 규칙을 사용합니다 두 화면의 장부·잔액 예시를 섞지 않습니다

**세 노드 비교는 컴퓨터 세 대의 동시 연산인가요**

아닙니다 한 서버에서 A/B/C의 독립 장부와 후보를 관리하고 번갈아 실제 해시를 계산하는 교육 모델입니다 실제 분산 P2P나 하드웨어 병렬 성능 시험은 아닙니다

**서버 준비 중일 때 누른 거래를 자동으로 다시 보내나요**

조회·준비 확인은 자동 복구하지만 변경 명령은 자동 재전송하지 않습니다 처리 여부가 불확실하면 연결 후 현재 기록을 확인하고 필요한 조작만 다시 합니다

**휴대폰 GPU가 없으면 실습이 안 되나요**

기본 CPU 모드로 진행할 수 있습니다 브라우저 GPU 지원은 기기마다 다르고 사용할 수 없으면 이유를 표시하며 CPU로 전환합니다 Python·C 고급 모드는 로컬 PC 전용입니다

**검증과 교육 효과를 어디까지 확인했나요**

날짜·환경별 실제 테스트와 배포 결과는 [검증 기록](../experiments/blockchain-practice/VERIFICATION.md)에 있습니다 이 시연은 실제 조작을 보여주지만 대규모 부하·실제 Bitcoin 호환성·학습 효과의 정량 향상을 입증하는 연구는 아닙니다
