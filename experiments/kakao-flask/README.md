# 교육용 블록체인 실습실 · Flask 2.0.0

지갑 → 거래 작성·전자서명 → Mempool → 작업 증명 → 블록 검증 → 노드 동기화를 직접 조작하는 팀 프로젝트용 로컬 교육 앱입니다. `codex/kakao-flask-run`에서 별도로 관리·실행하며, 개인 프로젝트인 기존 본체와 독립적입니다.

2026-11-16 개선판은 기존 Python 블록체인 모델을 유지하면서 실습 화면, 검증 규칙, 채굴 작업 제어, 실습별 저장과 API를 정리한 버전입니다.

## 빠른 실행

Python 3.13에서 확인한 직접 의존성은 Flask 3.1.3, ecdsa 0.19.2입니다. 이 폴더에서 PowerShell로 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

브라우저에서 `http://127.0.0.1:5000`을 엽니다. 실행 중인 터미널에서 Ctrl+C로 종료합니다. 화면 빌드나 Node.js 설치는 앱 실행에 필요하지 않습니다.

다른 포트 또는 저장 위치를 사용하려면 실행 전에 설정합니다.

```powershell
$env:PORT = '5003'
$env:KAKAO_PRACTICE_DB = 'C:\MyLab\practices.sqlite3'
.\.venv\Scripts\python.exe app.py
```

기본 저장 위치는 `instance/practices.sqlite3`입니다. 브라우저의 실습 식별 쿠키와 SQLite 기록으로 같은 실습을 이어 갑니다. 브라우저를 나누면 실습도 분리됩니다. 쿠키를 지우거나 새 실습을 만들면 다른 실습으로 시작합니다. 이 버전 이전의 서버 메모리 상태를 자동으로 가져오지는 않습니다.

서버 재시작 시 미완료 채굴·재채굴 작업은 취소합니다. 저장된 체인·지갑·대기 거래는 유지하며, 계산은 새 작업으로 시작합니다.

## 따라 해 보기

1. **홈**에서 실습 흐름과 시연 영상을 확인합니다. 영상은 이전 화면으로 녹화한 기본 원리 시연이며, 최신 조작은 화면의 단계 안내를 따릅니다.
2. **지갑**에서 Alice와 Bob을 만듭니다. 각각 50코인 지급 거래가 Mempool에 들어갑니다. 이때 확정 잔액은 아직 0입니다.
3. **채굴**에서 난이도 2를 적용하고 채굴합니다. Alice와 Bob의 확정 잔액은 각각 50이 됩니다.
4. **거래**에서 Alice → Bob, 20코인으로 작성 → 서명 → 제출합니다. 입력을 바꾸면 이전 작성·서명 결과가 무효화되므로 다시 작성합니다.
5. 다시 채굴하면 Alice 30 / Bob 70이 됩니다. A·B·C의 높이와 마지막 블록 해시를 비교합니다.
6. **블록·변조**에서 Node B의 블록 #2, 거래 #1의 금액을 1000으로 바꿔 봅니다. Merkle Root와 전자서명 검증이 실패하는 이유를 확인합니다.
7. **네트워크**에서 정상 노드의 체인으로 B를 동기화합니다. 오프라인 노드는 자체 채굴을 할 수 있지만, 분리된 동안 다른 노드에 블록을 보내거나 동기화하지 않습니다.

한 번 계산하기는 실제 Nonce 하나를 계산합니다. 느린 실행은 실제 표본을 읽을 시간을 두고 진행하며, 일시정지·재개·중지는 서버의 작업 상태와 함께 바뀝니다. 변조 후 재채굴도 묶음 단위로 진행하며 중간에 취소할 수 있습니다.

## 무엇을 개선했나

- 화면 제목과 안내를 짧게 정리하고 문장 끝 마침표·장식 영문·중복 소개를 제거했습니다. 상세 규칙은 펼침 영역으로 옮겼고, 모바일 버튼과 입력의 가독성을 높였습니다.
- 한 페이지에 길게 나열된 폼을 단계별 화면과 **목표 → 행동 → 관찰** 안내로 정리했습니다.
- 폼의 수신자·금액과 실제 서명할 거래가 어긋나지 않도록 이전 초안을 무효화합니다. 초기화와 제출 완료 뒤에도 버튼 상태를 함께 정리합니다.
- 오프라인 노드의 송신을 차단하고, 수신과 동기화가 같은 블록 검증·난이도 이력 규칙을 사용하도록 했습니다. 체인 선택은 유효한 누적 작업량을 비교합니다.
- 후보 블록의 작업 ID로 오래된 채굴 요청을 거부합니다. 실제 Nonce와 해시, 시도 횟수를 맞추고 일시정지·중지 상태를 구분합니다.
- 브라우저별 실습을 분리하고, 상태를 SQLite에 원자적으로 저장합니다. 저장 실패나 오래된 revision의 요청으로 실습 일부만 바뀌지 않게 처리합니다.
- 일반 지갑 목록에는 개인키를 넣지 않습니다. 필요한 지갑의 키를 명시적으로 열 때 별도 요청으로 가져옵니다.
- 잘못된 JSON·금액·노드·작업 ID에는 형식이 일정한 오류 응답을 제공합니다. 변조 재채굴은 사본에서 진행해 완료 전 취소하면 원래 체인을 유지합니다.
- 테스트의 서명 변조 대상이 faucet을 가리키던 오류를 바로잡고, 실제 서명된 송금을 검사합니다.

## 교육 모델의 범위

- 실제 자산·Bitcoin 네트워크와 연결하지 않습니다. A·B·C는 한 서버 프로세스 안의 모의 노드이고, 공동 수업 서버나 실제 P2P 네트워크는 아닙니다. 로컬 단일 프로세스에서 실행하며, 다중 서버의 연속 작업 스케줄러는 제공하지 않습니다.
- 계좌 잔액과 거래 순번을 사용합니다. UTXO·수수료·실제 Bitcoin 주소·표준 블록 직렬화는 구현하지 않습니다.
- SHA-256과 secp256k1 ECDSA, 거래 ID 기반 Merkle Tree를 실제로 계산합니다. 해시 앞의 0 개수, 고정 10코인 보상, 1회 50코인 지급은 교육용 규칙입니다.
- 난이도 변경은 이후 높이에 적용하는 실습 정책입니다. Bitcoin의 실제 난이도 조정 알고리즘을 구현한 것은 아닙니다.
- 실습 식별 쿠키는 교육용 실습을 구분하는 수단이며 로그인·사용자 계정 시스템은 아닙니다. 저장 DB에는 교육용 키가 포함됩니다. 서버는 기본적으로 127.0.0.1에만 바인딩합니다.
