채굴 설정

                

                
              

              

                Nonce를 바꿔 목표 해시를 찾으면 거래가 블록에 기록됩니다
연속 실행을 누르면 조건을 만족할 때까지 계산합니다
              

              

                
                

                  해시 앞자리 0 개수 (1~5)
                  
높을수록 평균 계산량이 늘어납니다

                

              

              

                
              

              

                목표 난이도 확인 중
              

              

                자세히 보기 · 작업 증명과 난이도
                
대기 거래를 모은 블록 헤더의 Nonce를 1씩 바꾸며 SHA-256 해시를 계산합니다 해시가 난이도 개수만큼 0으로 시작하면 작업 증명(PoW) 조건을 만족합니다

                
유효한 블록이 체인에 추가되면 선택한 지갑에 채굴 보상 10코인이 지급됩니다 난이도가 1 높아질 때마다 평균 시도 횟수는 약 16배 늘지만, 실제로 찾는 횟수는 매번 다릅니다

                
한 번 계산하기는 1회, 느린 실행은 약 250ms마다 1회 계산합니다 계산 중에는 일시정지하거나 작업을 중지할 수 있습니다

연결된 다른 노드는 블록을 검증한 뒤 자신의 체인에 추가합니다 같은 난이도에서도 먼저 찾는 노드와 시도 횟수는 달라질 수 있습니다

블록과 검증 결과

                

                
              

              

              

                블록별 검증 결과와 거래 내용을 확인하세요
              

              

              

                자세히 보기 · 블록 검증 원리
                
각 블록은 이전 블록의 해시를 담아 사슬처럼 연결됩니다 과거 데이터를 바꾸면 뒤따르는 블록과의 연결에도 영향을 줍니다

                
이 실습은 Genesis 블록의 일치 여부와 블록 해시·Merkle Root·작업 증명·이전 블록 연결·거래 규칙을 검사합니다 거래 규칙에는 전자서명과 잔액 검증 등이 포함됩니다

              

            

            

              

                

                  
변조 실험

                

                선택 노드의 체인 변경
              

              

                선택한 노드의 거래를 바꾸고 검증 결과를 비교하세요
체인이 무효가 되면 다른 노드와 동기화로 복구할 수 있습니다
              

              

                
              

              
채굴한 블록 필요

              

                
              

              

              

                자세히 보기 · 변조·재채굴과 체인 선택
                
    
                  
  1. 내용만 변경 · 저장된 해시와 거래 내용이 맞지 않게 됩니다
    2. 
                  
  2. Merkle·해시 재계산 · 해시를 다시 만들어도 작업 증명·블록 연결·거래 검증을 모두 통과해야 합니다
    3. 
                  
  3. 이후 블록까지 재채굴 · 작업 증명을 다시 수행해도 바뀐 송금의 서명이 유효해지지는 않습니다
    4. 
                

                
서명된 송금 거래의 금액이나 수신 주소를 바꾸고 새로 서명하지 않으면, 모든 블록을 다시 채굴해도 전자서명 검증에서 실패합니다

                
거래 #0은 서명이 없는 채굴 보상(coinbase)입니다 수신 주소를 바꾼 뒤 다시 채굴한 체인은 다른 거래 규칙도 만족하면 유효할 수 있습니다 끝 해시가 다르다는 이유만으로 배제되지는 않습니다

                
동기화할 때는 유효한 체인 중 누적 작업량이 더 큰 체인으로 교체합니다 현재 체인이 유효하고 작업량이 같으면 현재 체인을 유지하므로, 재채굴해 유효해진 체인도 다른 노드에 자동으로 채택되는 것은 아닙니다

                
재채굴은 복사본에서 진행됩니다 완료 전에 취소하면 원래 체인이 유지됩니다

노드를 오프라인으로 바꿔 채굴한 뒤, 온라인으로 되돌리고 동기화를 눌러 보세요
              

              

                자세히 보기 · 노드와 동기화 규칙
                
이 실습의 세 노드는 한 서버 안에서 같은 Genesis 블록으로 시작하며 각자의 체인과 대기열을 관리합니다 거래나 블록을 받으면 각자 규칙에 따라 검증합니다 끝 해시(tip) 옆의 색상 표시는 장부를 비교하는 보조 표시입니다

                
    
                  
  • 오프라인 · 로컬 채굴은 가능하지만 다른 노드와 거래·블록을 주고받지 않습니다
    • 
                  
  • 다시 연결 · 온라인으로 바꾸고 동기화하면 연결된 온라인 노드의 체인을 검증합니다
    • 
                  
  • 체인 선택 · 현재 체인이 유효하면 누적 작업량이 더 큰 유효 체인으로만 교체합니다 작업량이 같으면 현재 체인을 유지하며, 블록 수나 끝 해시 차이만으로 결정하지 않습니다
    • 
                  
  • 무효 체인 복구 · 현재 체인이 검증에 실패하면 연결된 온라인 노드의 유효한 체인으로 복구할 수 있습니다 이때 현재 체인의 길이나 작업량은 선택 기준으로 쓰지 않습니다
    • 
                

                
누적 작업량은 각 블록의 난이도에 따른 기대 작업량을 더한 값이며, 실제 해시를 시도한 횟수와는 다릅니다
