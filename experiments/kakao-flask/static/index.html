① Wallet · 공개키/개인키 · 잔액

지갑 = 개인키(서명용 비밀) + 공개키(검증용) + 주소(공개키의 해시, 계좌번호 역할). 잔액은 지갑에 저장된 숫자가 아니라 체인의 거래 내역을 처음부터 계산한 값입니다(선택한 노드 기준). 새 지갑은 faucet 거래로 학습용 코인을 받으며, 블록에 담겨야(채굴 후) 잔액에 반영됩니다.

④ Mining · Proof-of-Work

블록 헤더 + nonce를 SHA-256 해시해서, 결과가 난이도만큼의 0으로 시작할 때까지 nonce를 1씩 바꿔 가며 반복합니다. 난이도가 1 올라가면 평균 시도 횟수는 약 16배입니다.

⑤ Block · Blockchain ()

각 블록은 이전 블록의 해시(Previous Hash)를 담아 사슬로 연결됩니다. 아래 검증은 해시·Merkle Root·PoW·연결·거래(서명/잔액) 5가지를 모든 블록(Genesis 포함)에 대해 확인합니다.

🔧 변조 실험 (이 노드의 체인을 직접 조작)

블록 # 거래 # 새 값
거래 # 0은 채굴 보상(coinbase, 서명 없음)입니다. ③ 모드에서 서명된 거래를 바꾸면 PoW를 다 다시 해도 서명을 위조할 수 없어 실패하고, coinbase의 수신 주소를 바꾸면 이 노드만 유효해 보이지만 다른 노드 체인과 달라집니다(⑥ 표에서 tip 색상 비교).

⑥ Node 네트워크

모든 노드는 같은 Genesis에서 시작해 자기 체인·Mempool을 따로 가집니다. 거래/블록을 받으면 스스로 검증한 뒤에만 반영하고 이웃에게 전달합니다. tip 색이 같으면 같은 체인입니다. 노드를 오프라인으로 만들고 채굴한 뒤 다시 켜서 동기화해 보세요.
