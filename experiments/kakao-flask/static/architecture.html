1. 전체 시스템 구성도

사용자가 보는 웹 화면에서 시작해 웹 서버, 여러 Node, 핵심 모듈 순으로 이어지는 4개 계층 구조입니다. 위 계층이 아래 계층을 호출합니다.

① 사용자 화면 — 웹 브라우저 (HTML · CSS · JavaScript, static/index.html)

지갑 · 거래 화면지갑 생성, 서명, 제출
채굴 화면Nonce·Hash 변화, 난이도
체인 · 변조 실험 화면블록 카드, 검증 결과
노드 · 이벤트 로그노드별 체인 비교
▼ 요청  /  ▲ 응답  — HTTP (REST API, JSON)

② 웹 서버 — Python Flask (app.py)

지갑 · faucet API/api/wallets
거래 API/api/tx/prepare·sign·submit
채굴 API/api/nodes/·/mine
체인 · 변조 API/chain, /tamper
노드 제어 · 로그 API/sync, /online, /events

transaction.py거래 · 서명 검증
block.py해시 · Merkle Root · Nonce

2. 기능 블록도 (처리 흐름)

거래 하나가 만들어져 체인에 기록되고 모든 노드에 퍼지기까지의 흐름입니다. 각 블록에 담당 모듈과 입력·처리·출력을 적었습니다.

① 지갑 생성

모듈
wallet.py
입력
지갑 이름
처리
키 쌍 생성, 주소 계산
출력
개인키 · 공개키 · 주소

② 거래 생성 · 서명

모듈
transaction.py
입력
송신자, 수신 주소, 금액
처리
거래 내용을 해시 → 개인키로 서명
출력
서명된 거래

③ 검증 · Mempool 등록

모듈
mempool.py, blockchain.py(State)
입력
서명된 거래
처리
형식 · 서명 · 잔액 · 거래 순번 검사
출력
대기열 등록 또는 거부 사유

④ 채굴 (PoW)

모듈
miner.py, block.py
입력
대기 거래 + 채굴 보상
처리
Nonce를 바꿔 가며 해시 반복 계산
출력
난이도를 만족하는 해시의 블록

⑤ 블록 연결 · 체인 검증

모듈
block.py, blockchain.py
입력
완성된 블록
처리
Previous Hash 연결, 5가지 검증
출력
체인에 추가(또는 거부)

⑥ Node 전파 · 동기화

모듈
node.py
입력
새 거래 · 새 블록
처리
이웃에 전달 → 수신 노드가 검증 후 반영, 뒤처진 노드는 최장 유효 체인으로 동기화
출력
노드별 동일한 체인

⑦ 변조 실험 · 검증

모듈
blockchain.py, app.py
입력
변조할 블록 · 거래 · 값
처리
내용 변조 → 해시 재계산 → PoW 재수행 3단계
출력
어느 검증에서 걸렸는지 표시
※ 5가지 검증: 해시 · Merkle Root · 작업 증명 · 이전 블록 연결 · 거래(서명·잔액)

3. 모듈별 입력 · 처리 · 출력

모듈을 분리해 기능별로 따로 테스트할 수 있게 설계했습니다(단위 테스트 tests/test_core.py).

파일역할주요 클래스 · 함수입력 → 출력
wallet.py지갑Wallet, sign()이름 → 개인키 · 공개키 · 주소 · 서명
transaction.py거래 · 서명Transaction.sign(), verify_signature(), basic_check()거래 정보 → 서명, 검증 결과
block.py블록 · PoWBlock.calculate_hash(), calculate_merkle_root(), mine_to_target()거래 목록 + Nonce → 블록 해시
mempool.pyMempool (대기열)Mempool.add(), pending_state(), refresh()거래 → 등록 여부 · 거부 사유
miner.py채굴 (PoW)build_candidate(), mine()Mempool 거래 + 보상 → 채굴된 블록
blockchain.py체인 · 잔액 · 검증Blockchain.check_block(), validate_chain(), add_block(), State.apply()블록 · 거래 → 검증 결과, 계정 잔액
node.pyNode · 전파 · 동기화 (Mempool·채굴 모듈을 노드별로 사용)Node.receive_transaction(), start_mining(), mine_step(), receive_block(), resolve_conflicts()거래 · 블록 → 반영 여부, 전파 결과
app.py웹 서버 (API)/api/... 엔드포인트HTTP 요청 → JSON 응답
static/index.html웹 화면단계별 화면, 채굴 애니메이션사용자 조작 → API 호출 · 표시
static/glossary.js용어 도움말툴팁, 용어 사전용어 → 쉬운 설명

4. 요구사항 분석

과제 수행 계획서의 목표를 기능 요구사항(FR)과 비기능 요구사항(NFR)으로 정리했습니다.

번호요구사항구현 위치확인 방법
FR-01지갑 생성: 개인키 · 공개키 · 주소 생성과 표시wallet.py / 화면 ①지갑 생성 후 “키 보기”
FR-02학습용 코인 지급(faucet)과 잔액 표시blockchain.py(State) / 화면 ①채굴 후 잔액 반영 확인
FR-03거래 생성과 전자서명transaction.py / 화면 ②작성 → 서명 → 제출 3단계
FR-04거래 검증(형식 · 서명 · 잔액 · 거래 순번) 후 Mempool 등록mempool.py / 화면 ③변조·잔액 초과 거래 거부
FR-05채굴: Nonce 탐색, 난이도 조절, Hash 변화 표시miner.py, block.py / 화면 ④난이도별 시도 횟수 비교
FR-06블록 생성(Previous Hash, Merkle Root)과 체인 추가block.py, blockchain.py / 화면 ⑤블록 카드의 연결 확인
FR-07체인 검증과 데이터 변조 시뮬레이션blockchain.py, app.py / 화면 ⑤변조 3단계 실험
FR-08복수 Node 간 거래 · 블록 전파, 검증, 동기화node.py / 화면 ⑥노드별 tip hash 비교
FR-09전체 처리 과정과 데이터 변화를 웹 화면에 단계별로 시각화static/index.html / 화면 ⑦이벤트 로그
NFR-01이해 용이성: 비전문가도 이해할 수 있도록 용어 도움말과 단계별 화면 제공glossary.js용어에 마우스 올리기, 용어 사전
NFR-02안전성: 로컬(127.0.0.1)에서만 접속되어 외부 서버에 영향을 주지 않음app.py서버 바인딩 주소
NFR-03테스트 용이성: 모듈 분리와 기능별 단위 테스트tests/test_core.pypython -m unittest
NFR-04범위: 비트코인 전체가 아닌 핵심 동작만 단순화한 교육용 축소 모델README “단순화한 부분”문서 확인
