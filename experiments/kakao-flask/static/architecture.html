THE LEARNING JOURNEY

거래 한 건이 기록되는 순서

  1. 지갑 만들기: 주소를 만들고 학습용 지급 거래를 Mempool에 등록합니다.
  2. 거래 작성·서명: 송신자·수신자·금액·거래 순번을 정한 뒤 개인키로 서명합니다.
  3. 노드 검증: 형식·서명·잔액·순번을 확인하고 대기열에 보관합니다.
  4. 후보·채굴: 거래와 채굴 보상을 모으고 Nonce를 바꾸며 실제 SHA-256을 계산합니다.
  5. 전파·검증: 연결된 이웃 노드는 전달받은 블록을 각자 검증한 뒤 반영합니다.
  6. 변조·복구: 실패한 검사를 확인하고 정상 이웃의 유효 체인과 동기화합니다.

STATE & RECOVERY

무엇이 저장되고, 무엇이 다시 시작되나요?

브라우저별 실습
각 브라우저의 쿠키로 실습 공간을 구분합니다. 새로고침이나 서버 재시작 뒤에도 저장한 공간을 다시 불러옵니다. 별도 로그인 계정은 아닙니다.
지갑·장부
SQLite에 보관합니다. 현재 실습 초기화는 그 공간에만 적용합니다. 학습용 개인키는 서버에 보관하며, 명시적인 키 보기 요청에서만 화면에 표시합니다.
진행 중 계산
채굴 작업은 작업 ID로 구분합니다. 일시정지·재개·한 번 계산·중지가 가능하며, 서버 재시작 시 진행 중 작업은 중지 상태로 복원합니다.
재채굴 실험
작은 계산 묶음으로 복사본을 처리합니다. 완료 때 원래 체인에 반영하고, 완료 전 취소나 서버 재시작 시 미완성 복사본을 폐기합니다.
화면의 준비 데이터
아직 제출하지 않은 거래 작성·서명 단계와 선택한 표본은 현재 화면의 관찰 상태입니다. 입력이나 관찰 노드를 바꾸면 준비한 거래를 무효화합니다.

RULES & LIMITS

학습 모델의 범위

이 모델은 계정 잔액과 거래 순번을 사용합니다. 실제 Bitcoin의 UTXO 모델·주소 형식·바이너리 직렬화·이중 SHA-256·자동 난이도 조정·네트워크 P2P를 재현하지 않습니다. 실제 자산을 보관하거나 전송하지 않습니다.

작업 증명
선행 16진수 0의 개수로 난이도를 표현합니다. 난이도 1 증가 시 평균 계산량은 16배입니다. 변경된 정책은 지정한 다음 블록 높이부터 적용하며 과거 블록의 난이도를 소급 변경하지 않습니다.
체인 선택
블록 수만 비교하지 않고 유효한 체인의 누적 작업량을 비교합니다. 같은 작업량에서 임의로 장부를 바꾸지 않습니다.
네트워크 분리
오프라인 노드는 로컬 채굴을 할 수 있지만, 블록 전파와 이웃 동기화를 하지 않습니다. 다시 온라인으로 연결한 뒤 수동 동기화합니다.
변조와 서명
서명된 송금을 고치면 Merkle와 해시를 재계산하고 PoW까지 다시 수행해도 원래 서명은 맞지 않습니다. 서명이 없는 채굴 보상의 변경과 구분해 관찰해야 합니다.
