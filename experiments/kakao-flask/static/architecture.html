거래 한 건이 기록되는 순서

  1. 지갑: 주소를 만들고 학습용 지급 거래를 대기열에 등록해요
  2. 작성·서명: 송신자·수신자·금액·순번을 정하고 개인키로 서명해요
  3. 검증: 형식·서명·잔액·순번을 확인하고 대기열에 넣어요
  4. 채굴: 거래와 보상을 모아 후보를 만들고 Nonce를 바꾸며 해시를 계산해요
  5. 전파: 이웃 노드가 받은 블록을 각자 검증한 뒤 반영해요
  6. 변조·복구: 실패한 검사를 살펴보고 정상 이웃의 체인으로 복구해요

저장과 재시작

브라우저별 실습
쿠키로 실습을 구분하고 새로고침·서버 재시작 뒤에도 불러와요 로그인 계정과는 달라요
지갑·장부
SQLite에 저장하며 초기화는 현재 실습에만 적용해요 개인키는 서버가 보관하고 키 보기를 눌러야 표시해요
진행 중 계산
작업 ID로 구분하며 일시정지·재개·한 번 계산·중지가 가능해요 서버 재시작 시 진행 중인 계산은 중지해요
재채굴 실험
사본에서 나눠 계산하고 완료 후 체인에 반영해요 완료 전 취소하거나 서버를 재시작하면 사본을 버리고 원본을 유지해요
미제출 거래
작성·서명 결과와 선택한 표본은 화면에만 남아요 입력이나 관찰 노드를 바꾸면 거래를 다시 작성해야 해요

학습 모델의 범위

계정 잔액과 거래 순번을 쓰는 교육용 모델이에요 실제 비트코인의 UTXO·주소 형식·바이너리 직렬화·이중 SHA-256·자동 난이도 조정·P2P 네트워크와는 다르며, 실제 자산을 다루지 않아요

작업 증명
해시 앞의 16진수 0 개수가 난이도예요 1 높아지면 평균 계산량은 16배이며, 변경은 지정된 다음 높이부터 적용해요
체인 선택
유효한 체인의 누적 작업량을 비교해요 작업량이 같으면 현재 체인을 유지해요
네트워크 분리
오프라인에서도 채굴은 가능해요 블록 전파·동기화는 멈추며, 온라인 복귀 후 직접 동기화해야 해요
변조와 서명
서명된 송금을 고치면 해시·Merkle·PoW를 다시 맞춰도 서명 검증은 실패해요 서명이 없는 채굴 보상 변경과 구분해 보세요
