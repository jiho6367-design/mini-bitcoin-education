- Python 전체 207개 검사 완료, 환경 의존 17개 건너뜀, 실패 없음
- 기초 비교 신규 API 8개: 실제 해시·공정한 계산 순서·첫 발견·전파·지급 거래 포함·중지·재시작 복원·과거 ID/버전 거부·저장 실패 원복·과거 저장 형식 호환

## 초기 배정 설정·한 노드 채굴 (2026-11-16)

새 실습 생성 시 팀별 초기 금액을 1~10000 사이 정수로 설정하며 별도 링크·장부로 저장합니다. 기본 링크와 이전 Genesis·잔액은 바꾸지 않습니다. 초기 안내는 저장된 Genesis를 읽고 현재 잔액은 실제 UTXO를 읽습니다. 한 노드 채굴은 공유 엔진의 계산 대상을 서버에서 하나로 제한하며, 기존 대표 참여형 경쟁과 전파·검증·보상 규칙을 유지합니다.

- Python 전체 188개 검사 통과, PostgreSQL 등 환경 의존 17개 건너뜀
- 프런트 TypeScript·ESLint·단위 검사 82개·운영 빌드 통과
- 새 설정·단일 채굴 Chrome/Edge 4개 통과: 기존 기본 장부 유지와 별도 초기 50/250, 모바일 390px, 단일 B 실제 해시 계산·블록 발견, A/C 계산 0회, 보상 미성숙, 실제 전달 뒤 세 노드 독립 검증·재접속 확인
- API가 bool·소수·범위 밖 금액을 거부하며, 기본 이어가기 요청은 설정 금액으로 기존 실습을 초기화하지 않음
- 서버 교체 후 별도 금액과 두 링크 복원, 연결된 추가 실습 퇴출 거부, 빈 추가 실습 저장·복원과 기본 링크 보호 검사
- 실제 HTTP·WebSocket 프로세스 교체 검사에서 기본 방과 초기 50의 추가 방이 같은 링크·장부로 복원됨
- 단일 채굴 관찰자가 대표 없이 보상을 성숙시키는 실제 100블록 진행과 다른 노드 계산 0회, 경쟁 모드의 대표 접속 조건 유지 확인

운영 컨테이너·실제 무료 서버 배포 결과는 해당 커밋의 CI와 배포 확인 기록으로 별도 확인합니다.

## 서버 준비 안내·자동 연결 추가 검사 (2026-11-16)

공개 서버가 쉬거나 준비 응답을 반환할 때 사용자에게 Flask를 직접 실행하라고 안내하던 문구를 제거했습니다. 최초 연결은 설정 JSON이 정상적으로 반환될 때까지 기다리고, 연결 장애 때도 화면·입력·공유 링크를 유지합니다. 준비 확인은 GET만 재시도하며 정상 연결 후 주기적인 확인은 멈춥니다. 인터넷 끊김·접속 권한·입력 검증·사용량 오류를 구분합니다.

- 타입·린트·62개 단위 검사·빌드 통과
- Chrome·Edge 신규 준비/복구 검사 12개 통과, 최신 문구로 모바일 2개 추가 확인
- 기존 통합 화면 78개, 교사 없는 팀 실습 2개, 기초 화면 24개 브라우저 회귀 검사 통과
- Python 174개 중 157개 통과, PostgreSQL 전용 17개는 환경 변수 없이 건너뜀
- 실제 서버가 거래 초안·지갑 생성 요청을 처리한 뒤 브라우저의 응답만 502로 바꿔, 복구 후 조회만 수행하고 변경 요청을 중복 전송하지 않는지 확인
- HTML 준비 페이지·일시적인 503·응답 시간 초과를 재현하고 정상 설정 응답 이후 같은 모바일 참여 링크로 자동 진입 확인
- 403과 실제 잔액 부족 오류는 준비 상태로 바꾸지 않으며, 복구 후에도 불확실한 작업 안내와 기존 저장 실패 원문을 보존
