# Flask 2.0.0 검증 기록

검증일: 2026-11-16 (한국 시간). 대상: `codex/kakao-flask-run`의 Flask 앱. 개선 전 기준은 `01b31ad`입니다. 기존 React 앱과 Flask 앱의 버전·실행 경로는 별도로 유지합니다.

## 재현했던 문제와 수정

| 개선 전 문제 | 수정 후 확인한 동작 |
| --- | --- |
| 작성 뒤 수신자·금액을 바꾸어도 이전 거래가 서명·제출됨 | 입력·관찰 노드 변경 시 초안과 서명을 무효화하고 버튼을 잠금 |
| 오프라인 A의 채굴 블록이 B·C에 전파됨 | 분리 상태에서 A만 높이가 증가하고, 연결 후 수동 동기화로 B·C가 따라옴 |
| 직접 수신과 체인 동기화의 난이도 검증이 다름 | 높이별 난이도 정책과 거래 검증을 함께 적용하고 유효한 누적 작업량 비교 |
| 서명 변조 테스트가 서명 없는 faucet 거래를 대상으로 검사함 | 실제 서명된 송금을 변조하고 재채굴 뒤에도 서명 실패 사유를 확인 |

추가한 기능도 별도 담당자가 재검토했습니다. 그 과정에서 확인창을 수락한 초기화 요청이 계산 요청 때문에 누락되는 문제, 새 채굴 작업에 이전 성공 문구가 남는 문제, 다른 서버 인스턴스의 오래된 캐시가 실습 변경을 막는 문제를 재현해 수정했습니다. 단순한 검토자 동의 대신 실제 요청·상태·회귀 검사로 확인했습니다.

Windows, Python 3.13, Node.js 24.19.0에서 실행했습니다. Flask 3.1.3과 ecdsa 0.19.2를 사용했습니다.

브라우저 검사는 별도 포트 5010과 테스트 DB를 사용했습니다. 지갑 생성 → 지급 채굴 → 거래 작성·변경·재작성·서명·제출 → 채굴 → Alice 30/Bob 70 → B 변조 검출 → 동기화 복구를 실제 버튼으로 확인했습니다. 오프라인 채굴, 한 번 계산·느린 실행·일시정지·재개·중지, 명시적 키 조회·닫기, 초기화 뒤 서명 무효화, 실습 분리·새로고침 복원도 검사했습니다.

초기화·새 실습 확인창의 경합 검사는 실제 서버가 계산한 응답을 잠시 보류한 상태에서 확인을 누른 후, 응답을 전달하고 초기화 요청이 실제 처리되는지 확인합니다. PoW 응답이나 해시를 꾸며내지 않습니다.

1440×1000 데스크톱과 390×844 모바일에서 배치와 가로 넘침을 확인했고, 라이트·다크 화면을 캡처해 직접 살펴봤습니다. 키보드 용어 검색·닫기, 구성도 이동과 테마 유지, 홈을 떠날 때 실제 영상 정지도 검사했습니다.

서버 재시작 검사는 서로 다른 프로세스 ID의 HTTP 서버 두 개를 순서대로 실행합니다. 같은 쿠키의 지갑·대기 거래·실습 ID 복원을 확인합니다. API 검사에서는 저장 실패 시 원복, 이전 revision 거부, 캐시 갱신, 진행 작업 ID와 취소, 재채굴 복사본의 원자적 적용을 확인합니다.

## 유지한 영상과 확인 한계

홈의 기존 자막 영상은 2880×1800, 약 224초입니다. 실제 재생 시간을 검사했으며 파일의 SHA-256은 개선 전과 같습니다.

```text
ffd9654dff2643712161a34756f6368f8e87b39cf6be89b57803ffa4f4859398
```

영상은 이전 UI로 녹화했으므로 화면에도 그 점을 표시했습니다. 최신 UI의 새 시연 영상은 이번 작업에 포함하지 않습니다.

이 검사는 로컬 교육용 축소 모델의 동작을 확인합니다. 실제 Bitcoin 호환성, 다중 서버의 연속 작업 처리, 배포 운영·성능 부하 검증을 의미하지 않습니다. UTXO·수수료·교실 권한 등 기존 본체의 별도 기능을 이 Flask 앱에 합치지는 않았습니다.

## Flask 3.0.0 통합 확인 (2026-11-16)

개인 프로젝트의 현재 3.2.0 소스와 화면을 팀 앱 내부의 독립 사본으로 가져왔습니다. 원본 개인 프로젝트와 그 DB는 수정하지 않았습니다. 원본 해시는 `education_engine/PROVENANCE.json`에 기록했으며 복사 후 재대조했습니다. 별도 FastAPI 서버 없이 Flask 하나가 통합 React 화면·기초 화면·HTTP·공동 수업 WebSocket을 제공합니다.

| 검사 | 최종 결과 |
| --- | --- |
| 전체 Python unittest, ResourceWarning을 오류로 처리 | 116개 통과, 종료 시 DB 연결 경고 없음 |
| 통합 화면 타입·ESLint·Vitest·빌드 | 통과, 40개 단위 검사 |
| 기존 기초 화면의 UI 상태 검사 | 10개 통과 |
| 통합 화면 Chrome·Edge 전체 E2E | 78개 통과, 브라우저별 39개 |
| 기초 화면 Chrome·Edge 전체 E2E | 24개 통과, 브라우저별 12개 |
| 저장소 전체 ESLint·변경 diff 검사 | 통과 |
| Windows CMD → PowerShell 실행기 | 별도 5004 포트에서 시작·건강 검사·종료 확인 |

Python 검사는 UTXO·수수료·코인베이스·100블록 성숙, 동률·부모 대기·큰 작업량 분기 채택과 고아 거래 복구, 저장 실패 원복·검색·백업 복원·손상 거부를 포함합니다. 실제 임시 HTTP 서버와 WebSocket 클라이언트로 인증 첫 프레임, snapshot→seq/baseSeq patch, 권한 변경·재연결·잘못된 토큰과 출처 거부를 확인했습니다.

실제 브라우저에서는 거래 추적·UTXO 선택·서명·수수료·경쟁·보상 성숙 후 송금·메시지 수동 전달·변조·보관함·HTML·복원·공동 실습과 역할 변경을 확인했습니다. 추가 모드 전환 사례는 통합→기초 지갑 생성→통합→공동→통합을 이동하고, 기초 지갑 추가가 UTXO 장부의 Alice 100/Bob 0을 바꾸지 않는지 확인합니다. 영상의 2880×1800·224초대 메타데이터와 화면 이동 시 재생 중지도 확인했습니다.

운영 접근 경계도 검사했습니다. 개인 실습·보관함·키는 서명된 브라우저 소유자 쿠키로 제한하고, 교사·대표·관찰자는 별도 참가 권한을 확인합니다. DB 두 개를 같은 파일로 지정하면 원본을 수정하지 않고 거부합니다. 모르는 API 경로는 기초 실습을 새로 생성하지 않습니다. 생성·블록·대기열 등의 한도에 도달해도 읽기·저장·중지·전달·삭제 등 복구 조작을 유지합니다.

독립 검토에서 생성/퇴출 잠금의 교착과 Windows 백업 연결 누수를 재현해 수정했으며 같은 재현 조건으로 재검사했습니다. 마지막 전체 검사는 실습 한도·종료 정리를 반영한 코드에서 수행했습니다. 캡처는 라이트·다크·모바일의 실제 테스트 화면입니다.

실행기 확인은 의존성과 화면 빌드를 별도 검증한 뒤 `-SkipInstall -SkipBuild`로 수행했습니다. 새 PC에서의 전체 설치를 재현한 것은 아닙니다. 운영 Dockerfile·Gunicorn 설정은 작성·소스 검토했지만 이 환경에는 Docker가 없어 이미지 빌드와 Linux 실행은 수행하지 않았습니다. 실제 인터넷 배포·HTTPS/WSS·영속 볼륨·재배포 및 공개 부하는 별도 확인이 필요합니다. 운영 범위는 [배포 안내](DEPLOYMENT.md)에 있습니다.

## 운영 배포 준비·재시작 추가 확인 (2026-11-16)

- 전체 Python 검사 126개 통과, ResourceWarning을 오류로 처리
- 서로 다른 실제 서버 프로세스에서 개인 UTXO 장부·소유 쿠키·키·보관함, 기초 지갑·미확정 지급, 공동 수업 저장·새 방 복원을 확인
- 개인 실습의 Alice/Bob 69·30, 공동 수업의 69·130·100 잔액이 재시작 뒤 동일함을 확인
- 저장 소유자 외 브라우저의 기록·키 접근을 거부하고, 종료 전 방·교사·대표 권한은 승계하지 않음
- HTTPS 인입 프록시에서 같은 출처의 변경 허용·다른 출처 거부·Secure 쿠키 확인
- 운영 진입점의 지정 경로 제한·권한 전환·쓰기 실패 시 시작 거부와 SIGTERM 전 WebSocket 종료 신호 검사
- Render Blueprint를 공식 JSON Schema로 검증

위 프로세스 검사는 임시 DB의 Windows Flask 서버를 사용했습니다. Linux Docker·Gunicorn 검사는 별도 GitHub Actions 결과로, 실제 Render의 HTTPS/WSS·영속 디스크·재시작 검사는 공개 배포 후 결과로 구분합니다.

## Linux 운영 컨테이너 확인 (2026-11-16)

[GitHub Actions 실행 43741142718](https://github.com/jiho6367-design/mini-bitcoin-education/actions/runs/43741142718)에서 다음 검사를 모두 통과했습니다. 소스 커밋은 `e228206359f8a8d20ddfee2ff4698c91d1dd5549`입니다.

- Ubuntu 표준 러너의 Node 24·Python 3.13 다단계 Docker 이미지 실제 빌드
- root 소유의 빈 볼륨을 마운트한 뒤 Gunicorn PID 1과 두 DB가 UID/GID 10001로 동작하고 다른 사용자 권한 비트가 없는지 확인
- 실제 HTTP·WebSocket으로 개인·기초·공동 실습 기록 생성
- 인증된 WebSocket이 열린 상태에서 SIGTERM 정상 종료, 강제 종료 없이 서버 exit code 0 확인
- 기존 컨테이너를 완전히 삭제하고 다른 컨테이너 ID로 같은 볼륨을 마운트한 뒤 두 DB·소유 쿠키·키·저장 수업·새 권한 복원 확인
- 검사 통합·공동 기록과 비공개 상태 파일 정리 확인

프런트엔드 운영 의존성 `npm audit --omit=dev`도 알려진 취약점 0개입니다. 운영 이미지는 Node·node_modules를 포함하지 않습니다. 이 검사는 외부 공개 주소를 배포하지 않으며 실제 Render의 HTTPS/WSS·호스팅 디스크·재시작 확인은 남아 있습니다.
