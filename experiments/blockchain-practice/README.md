## 실행

Windows에서는 Python 3.13과 Node.js 24가 필요합니다. 이 폴더의 **Start-Team.cmd**를 실행하면 팀 전용 가상환경·화면 빌드를 준비한 뒤 Flask 서버를 시작합니다. 기본 주소는 `http://127.0.0.1:5003`이며 Ctrl+C로 종료합니다. 포트가 이미 사용 중이면 기존 프로세스를 종료하지 않고 안내합니다.

```powershell
.\Start-Team.cmd
# 다른 포트
.\Start-Team.cmd -Port 5004
```

직접 실행하려면 다음 순서를 사용합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd frontend
npm.cmd ci
npm.cmd run build
cd ..
$env:TEAM_TEACHER_SECRET = '교사가 정한 긴 무작위 비밀코드'
$env:PORT = '5003'
.\.venv\Scripts\python.exe -B app.py
```

실행기는 비밀코드가 없으면 `instance/teacher-key.txt`에 무작위 코드를 생성해 재사용합니다. 참가자에게는 교사용 비밀코드 대신 방 코드·참여 링크를 전달합니다. 실습에 실제 자산이나 실제 지갑의 키를 넣지 않습니다.

## 실습 화면

| 경로 | 기능 |
| --- | --- |
| `/` · `/basic` | 기초 실습: 지갑·송금·전자서명·한 노드 채굴·세 노드 채굴 비교·변조·복구 |
| `/?classroom=teacher` | 교사 방 생성·대표 지정·전파·실행 제어 |
| `/?classroom=join` | 이름으로 팀 실습 시작·참여, A/B/C 직접 선택, 공동 실행 제어 |
| `/hashcash` | 넌스 찾기: 메시지·난이도 설정, 실제 SHA-256 탐색·중지·결과 검증 |
| `/advanced` | 이전 개인 실습·보관함 호환 경로, 공개 모드 메뉴에서는 제외 |

공개 모드 메뉴는 **기초 실습 → 공동 실습 → 넌스 찾기** 순서입니다. 기존 공동 링크의 `classroom`·`room` 쿼리는 그대로 사용합니다. 같은 Flask 서버에서 화면을 제공하고 공동 실습의 HTTP·WebSocket은 `/api/education`, 기초 실습 API는 `/api`를 사용합니다. 이전 실습의 코드·보관함·API는 보존하며 별도 FastAPI 서버는 필요하지 않습니다.

기초 채굴의 기본은 **한 노드 채굴**입니다. **세 노드 비교**를 선택하면 같은 장부 끝에서 A/B/C가 실제 해시를 계산하고 첫 블록 발견 시 멈춥니다. 노드별 계산 횟수·Nonce·해시와 블록 전달 결과를 비교합니다. 비교에는 기초 실습의 거래·장부를 사용하며 공동 실습 장부와 합치거나 초기화하지 않습니다.

세 화면의 배경·카드·버튼·강조색은 `static/team-theme.css`에서 함께 관리합니다 시스템·라이트·다크를 지원하고 화면을 오가도 선택을 유지합니다 이전 기초 테마는 공통 선호가 없을 때만 읽어 이전하며 원래 키와 개인 앱 설정은 변경하지 않습니다

### 넌스 찾기

`codex/hashcash-only`의 해시캐시 실습을 팀 웹 앱에 맞춰 옮겼습니다 **메시지 → 목표 난이도 → 탐색 시작** 순서로 사용하고, 발견한 넌스는 **해시 다시 검증**으로 확인합니다 난이도는 앞의 16진수 0 개수이며, 1 증가할 때 평균 계산량은 16배가 됩니다 실제 발견 시간은 매번 다릅니다

계산 규칙은 원본과 같은 단일 `SHA256(UTF8(메시지 + 10진수 넌스))`입니다 공백·줄바꿈을 그대로 포함하고, 넌스는 0~18446744073709551615 범위의 정수입니다 HTTPS 또는 localhost에서 동작하며, PC·휴대폰에서 기본 웹 모드를 별도 프로그램 없이 사용할 수 있습니다

| 연산 방식 | 실제 실행 환경 |
| --- | --- |
| 자동 | WebGPU를 실제 검증한 뒤 GPU 사용, 지원하지 않으면 브라우저 CPU |
| CPU | 브라우저 Web Crypto SHA-256 |
| GPU | 접속한 기기의 WebGPU에서 실제 병렬 SHA-256 |
| CPU+GPU | 브라우저 CPU와 GPU가 겹치지 않는 넌스 구간을 동시에 계산 |
| Python CPU+GPU · PC 전용 | PC에서 실행한 블록체인 실습실의 Python CPU·NVIDIA CUDA |
| C CPU+GPU · PC 전용 | PC에서 실행한 블록체인 실습실의 C/OpenSSL 스케줄러·NVIDIA CUDA |

화면에는 선택한 모드와 별개로 **실제 장치·CPU/GPU별 완료 계산 수·전환 이유**를 표시합니다 WebGPU가 없거나 장치 초기화·자체 검증·계산 중 오류가 나면 CPU로 전환합니다 GPU는 원본과 같이 UTF-8 메시지 35바이트까지 지원하며, 긴 입력은 CPU로 계산합니다 GPU 병렬 배치는 발견 이후의 추가 계산도 완료 횟수에 포함합니다 CPU+GPU는 항상 더 빠르거나 최소 넌스를 찾는다고 보장하지 않습니다 브라우저 연산은 서버의 GPU나 저장 장부를 사용하지 않으며 화면을 떠나면 종료합니다

발견 결과는 **해당 브라우저에 최근 50개까지 저장**합니다 새로고침 뒤에도 남지만 다른 기기와 공유되지 않으며 브라우저 데이터를 지우면 삭제됩니다 기존 CPU 기록과 저장 키를 유지하고, 새 기록에는 실제 연산 정보도 남깁니다 팀 공동 실습의 서버 저장 기록과는 별개입니다

#### 선택 사항: Python·C 고급 모드

**Start-Team-Native.cmd** 또는 `Start-Team.cmd -Native`로 PC 전용 엔진을 켭니다 기본 웹의 CPU·GPU 기능에는 이 과정이 필요하지 않습니다 공개 무료 Render에서는 PC 엔진을 실행하지 않으며, 해당 모드를 선택하면 안내 후 브라우저 CPU로 전환합니다 로컬 PC 엔진은 CUDA가 없으면 Python CPU로, C만 준비된 경우 C CPU로 전환하며 실제 사용한 엔진을 표시합니다

```powershell
# 선택 GPU 의존성 설치 후 PC 모드 실행
.\Start-Team.cmd -Native -InstallGpu
# 이미 GCC·OpenSSL 개발 환경이 있는 PC에서 C 엔진 빌드·검증까지
.\Start-Team.cmd -Native -InstallGpu -BuildNative
```

C 도구 경로는 `-Compiler`와 `-OpenSSLRoot`로 지정할 수 있습니다 자세한 조건과 출처는 [PC 엔진 안내](native_hashcash/README.md)에 정리했습니다 서버는 이 PC의 루프백 연결에서만 고급 연산을 허용하고, 브라우저마다 작업을 분리합니다 중지·페이지 이동 시 작업을 취소하며 연결이 사라진 작업은 조회 임대 시간이 지나면 중지합니다 기존 기초·공동 DB에 새 연산 결과를 기록하거나 데이터를 이전하지 않습니다

## 공통 실습 가이드

입장 화면의 기본 동작은 **기존 실습에 입장**입니다 공유 링크라면 별명만 적으면 됩니다 혼자 연습하거나 초기 금액을 정하려면 **새 실습 만들기 → 별명 → 새 실습 시작**을 사용합니다 중복 통합 실습 버튼과 팀 실습 시작 탭은 없애고 최상단 모드 링크만 유지했습니다

입장 후 **쉬운 실습**은 현재 필요한 동작 하나를 안내합니다 혼자라면 **팀 A로 시작 → 자동 전달 켜기 → 송금 내용 확인 → 전자서명하기 → 거래 보내기 → 채굴 준비 → 채굴 시작 → 결과 보기**를 누릅니다 B·C 담당자는 없어도 됩니다 작성·서명·전송·채굴은 버튼을 누를 때 각각 실제 명령을 실행하며 화면을 열기만 해서는 실행하지 않습니다

예약된 대기 거래가 있으면 새 송금을 요구하지 않고 그 거래의 채굴을 이어갑니다 완료 뒤에는 **다음 송금 연습**으로 진행합니다 자세한 역할·거래·채굴·노드 화면은 **직접 조작 · 팀 선택과 거래·채굴 상세**를 펼치거나 가이드 이동 버튼으로 엽니다

입력한 별명은 재입장 시에도 반영하고 **별명 변경**으로 수정할 수 있습니다 내 별명과 접속 중인 참가자는 항상 표시하며, 과거 참여 기록은 별도로 펼칩니다 자동 재접속은 마지막 별명을 유지합니다

상세 **공통 실습 가이드**는 기본 접힘이며 실제 완료 단계가 자동 체크됩니다 펼치면 다음 할 일과 관련 화면 이동 버튼을 볼 수 있고 **가이드로 돌아가기**는 설명을 자동으로 펼칩니다

A/B/C는 한 명씩 맡고 공통 버튼은 정한 진행자가 조작합니다. 한 명 이상 대표가 있으면 나머지는 관찰자로 함께 볼 수 있습니다. 안내 이동과 완료 체크는 거래·채굴을 실행하지 않으며 실제 조작은 해당 화면에서 직접 합니다.

**가이드 확인 거래**와 거래 화면의 **관찰 거래**는 같은 거래를 선택합니다. 대기 중인 거래와 새로 접수된 거래를 따라가며, 예전 완료 거래는 직접 선택했을 때만 진행 결과를 표시합니다. 새 실습은 **새 거래 기다리기**를 선택합니다. 선택한 거래는 같은 브라우저의 저장소가 사용 가능하면 새로고침 뒤에도 유지합니다.

단계 판정은 현재 방 상태를 사용합니다. 역할·자동 전달 설정을 바꾸거나 체인이 재구성되면 완료 표시도 갱신됩니다. 마지막 단계는 선택한 거래가 세 노드의 유효한 체인에 같은 블록으로 포함되고 최신 블록까지 일치할 때 완료됩니다. 연결이나 저장 상태가 불확실하면 마지막 확인 결과를 표시합니다.

## 시작 코인과 사용 가능액

공동 실습의 거래 화면에서 A/B/C 팀 지갑의 시작 금액과 현재 잔액을 구분합니다. 기존 기본 실습은 팀마다 100코인씩 시작합니다. **새 실습 만들기**에서는 **팀별 초기 코인**을 1~10000 사이의 정수로 정합니다. 각 팀에 같은 금액을 한 번 배정하고 별도 참여 링크에 저장합니다. 기존 기본 링크와 장부는 유지되며, **기존 실습에 입장**은 그 링크의 실습을 이어 엽니다. 추가 참가·재접속은 코인을 새로 지급하지 않습니다.

현재 잔액은 송금·수수료에 따라 변하며, 채굴 보상은 별도 보상 지갑에 쌓입니다. 초기 배정 표시는 저장된 Genesis에서 읽으므로 새로고침이나 서버 재시작 후에도 선택한 금액을 정확히 보여줍니다.

카드는 확정 잔액·사용 가능액·대기 거래 예약 금액을 구분합니다. 예약 금액은 실제로 잠긴 자기 지갑의 UTXO를 합산하고 채굴 보상 성숙 대기는 따로 표시합니다. 잔액이 있어도 사용 가능액이 0이면 해당 카드에서 이유를 바로 확인할 수 있습니다. 펼침 설명은 초기 입력 100으로 송금 10·수수료 1을 제출하면 100 전체가 예약되고, 채굴·전파 뒤 거스름돈 89를 사용할 수 있는 예시를 보여줍니다.

## 한 노드 채굴과 경쟁

공동 실습의 **채굴 → 한 노드 채굴**에서 A/B/C 중 하나와 계산 속도를 선택하고 **선택 노드 후보 준비 → 채굴 시작 / 계속**을 누릅니다. **한 번 계산**은 실제 해시를 한 번 계산합니다. 선택한 노드만 채굴하고 첫 블록 발견 시 멈춥니다. 다른 노드는 자동·수동 메시지 전달 뒤 블록을 독립 검증합니다. 팀 대표 역할 없이 공통 버튼으로 진행할 수 있고 거래 서명은 기존처럼 자기 팀 대표만 합니다.

**채굴 경쟁**에서는 기존 세 후보 준비·각 팀 참여·전체 시작을 사용합니다. 방식 화면만 바꾸면 서버 상태는 바뀌지 않습니다. 새 후보 준비는 진행 중인 계산을 교체하며 기존 체인과 잔액은 유지합니다. 기본 링크는 항상 유지하고, 무료 서버 자원을 위해 기본 실습과 추가 실습 3개까지 동시에 메모리에 유지합니다. 접속자가 없는 추가 실습은 저장 후 일시정지하고 같은 링크에서 다시 복원합니다.

## 저장과 복구

온라인 운영은 Neon PostgreSQL의 `team_basic`·`team_education`·`team_control` 스키마를 사용합니다 다음 파일 경로는 `TEAM_DATABASE_URL`을 지정하지 않은 로컬 실행의 기본값입니다

| 데이터 | 로컬 기본 파일 | 변경 환경 변수 |
| --- | --- | --- |
| 기존 기초 실습 | `instance/practices.sqlite3` | `KAKAO_PRACTICE_DB` |
| 통합·공동 실습, 소유자 정보 | `instance/education.sqlite3` | `TEAM_EDUCATION_DB` |

두 DB는 규칙·서명이 다른 별도 장부입니다. 같은 파일 경로를 지정하면 실행을 거부합니다. 기존 기초 실습을 UTXO로 자동 변환하지 않으며 기존 파일은 그대로 기초 화면에서 사용합니다. 원본 개인 프로젝트의 DB·쿠키·환경 변수를 가져오지 않습니다.

통합 실습은 같은 브라우저의 서명된 소유자 쿠키로 보관함 접근을 제한합니다. 쿠키를 지우면 이전 개인 보관함에 접근할 수 없으므로 결과 HTML·운영자 백업을 별도로 보관하세요. 팀 실습은 공유 코드와 저장 기록을 함께 보관하며, 같은 브라우저는 재시작 후 새 접속 권한을 자동으로 받습니다. 역할은 다시 선택하고 진행 계산은 멈춘 상태에서 이어갑니다. 쿠키를 지우거나 다른 기기를 쓰면 같은 링크에서 이름으로 다시 참여할 수 있습니다. 팀 실습 시작을 다시 눌러도 기존 공유 장부를 초기화하지 않습니다. 교사 비밀코드가 필요한 기존 교실 모드는 별도로 유지합니다.

운영 중 통합 DB의 일관된 백업과 서버 종료 후 복원을 지원합니다.
아래 명령은 로컬 SQLite용입니다. 공개 Neon 배포에는 PostgreSQL 백업을 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m education_engine.service.backup backup instance/education-backup.sqlite3
# 서버를 모두 종료한 뒤 복원
.\.venv\Scripts\python.exe -m education_engine.service.backup restore instance/education-backup.sqlite3 --confirm-server-stopped
```

기존 백업 이름은 덮어쓰지 않으며 복원 전 DB도 새 이름으로 보관합니다. 백업에는 교육용 개인키와 소유자 정보가 포함되므로 공유하지 않습니다. 결과 HTML은 서버 없이 읽는 결과 파일이며 복원용 DB가 아닙니다.

## 운영 배포

단일 프로세스 Gunicorn과 외부 PostgreSQL로 무료 공개 배포했습니다. 실제 HTTPS·WSS와 Render 재시작 전후 기록·소유권 복원을 확인했습니다. 절차·무료 한도·수업 복구 방법은 [배포 안내](DEPLOYMENT.md), 검사 결과는 [검증 기록](VERIFICATION.md)에 있습니다. `app.py`의 Flask 개발 서버는 로컬 확인용입니다.

이 앱은 하나의 서버 안에서 A/B/C 모의 노드를 실행하는 교육 모델입니다. 실제 Bitcoin P2P 노드·실제 자산 지갑·상시 다중 서버 서비스가 아닙니다. 기초 모드는 잔액·순번, 통합 모드는 교육용 UTXO를 사용하며 주소·직렬화·발행·난이도는 실제 Bitcoin과 다릅니다.
